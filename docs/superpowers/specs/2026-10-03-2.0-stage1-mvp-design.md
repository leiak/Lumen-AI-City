| Kafka broker | 9092 | |
| Kafka zookeeper | 2181 | |

**端口分配原则**：
- 双实例（city_a / city_b）：同类型服务错开端口（web 3000/3001，api-gateway 8080/8081）
- 共享层（a2a-gateway / saga / memory / Milvus / Kafka）：独占端口段
- ws-gateway city_b 用 8085 而非 8083 是为了**避开共享层 a2a-gateway HTTP 8083**

### 4.4 关键架构决策

1. **跨城双实例**（而非多副本）—— 同一容器类型两个实例，PG/Redis 分 namespace，通过共享 a2a-gateway + Milvus + Kafka 互通。
2. **NPC 全局 ID** —— `npc_<city>_<slug>` 格式（如 `npc_a_wang_boss`、`npc_b_grace_healer`），a2a-gateway 维护 city → world-engine 路由表。
3. **mTLS 双向认证** —— 自签 CA + 短期证书（90 天 + 到期前 7 天自动轮换），不引 cert-manager。
4. **Milvus 命名空间隔离 + 跨城只读转发** —— `mem_<city>_<npc_slug>` collection；B 城玩家访问 A 城 NPC 时只读访问该 collection，不复制到 B 城 PG。
5. **Saga 触发 Kafka topic** —— `saga.npc.action`、`saga.compensation.request` 两个 topic。
6. **桶 2 占位接口** —— `npc_templates` 加 `avatar_url` 字段（optional）；`/v1/notification/subscribe` 空实现；client-reconciler 包预留接口不实现。

## 六、跨城联邦机制

### 6.1 NPC 全局 ID 与路由表

**ID 格式**：`npc_<city>_<slug>`
- `npc_a_wang_boss`（A 城王老板）
- `npc_b_grace_healer`（B 城小护士 grace）

**路由表 schema**（a2a-gateway 内存 + PG 双写）：
```sql
CREATE TABLE a2a_npc_routes (
  npc_id TEXT PRIMARY KEY,
  city TEXT NOT NULL,
  world_engine_addr TEXT NOT NULL,
  grpc_cert_fingerprint TEXT NOT NULL,
  enabled BOOLEAN DEFAULT TRUE,
  last_heartbeat_ms BIGINT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

- a2a-gateway 启动时全表加载到内存 map（O(1) 查表）
- world-engine 每 30s 心跳更新 `last_heartbeat_ms`，超过 90s 标记离线
- 跨城 NPC 请求流程：`/v1/npc/npc_b_grace_healer/talk` → a2a-gateway 路由表查 `city_b` → 转发到 `world-engine-b:50051`

### 6.2 mTLS 双向认证

**自签 CA + 短期证书**（不引 cert-manager）：
```bash
# scripts/init-certs.sh（容器启动时跑 1 次）
./scripts/gen-ca.sh aicity-ca
./scripts/issue-cert.sh world-engine-a city_a
./scripts/issue-cert.sh world-engine-b city_b
./scripts/issue-cert.sh a2a-gateway federation_hub
```

**a2a-gateway 配置**：
```yaml
tls:
  cert: /etc/a2a/certs/a2a-gateway.crt
  key: /etc/a2a/certs/a2a-gateway.key
  ca: /etc/a2a/certs/aicity-ca.crt
  client_ca: /etc/a2a/certs/aicity-ca.crt
  min_version: 1.3
```

**world-engine 配置**（rustls + rustls-pemfile）：
```toml
[grpc.tls]
cert = "/etc/world/certs/world-engine-a.crt"
key = "/etc/world/certs/world-engine-a.key"
ca = "/etc/world/certs/aicity-ca.crt"
```

### 6.3 跨城记忆共享策略

**Milvus 命名空间隔离 + 跨城只读转发**：
- 每个 NPC 的 Milvus collection 命名 `mem_<city>_<npc_slug>`
- B 城玩家访问 A 城 NPC 时：
  1. a2a-gateway 路由到 `world-engine-a`
  2. world-engine-a 调用 memory-service 的 `recall(npc_id, player_id, top_k=5)`
  3. memory-service 从 `mem_a_wang_boss` 召回该 player 的历史 embedding
  4. **不复制到 B 城 PG**（避免双写一致性），只读访问
- B 城玩家在 A 城 NPC 留下的记忆**只在 A 城 Milvus 留存**（per-NPC 归属）
- 例外：B 城 NPC 也能召回该 player 在 B 城的记忆（per-player 全局视角）—— 通过跨 collection 查询，agent-os 层聚合

### 6.4 跨城事件流

- 跨城 NPC 互动事件 publish 到 Kafka topic `a2a.cross_city.event`
- ws-gateway 订阅该 topic 后向**两个城**的 ws hub 推 fanout
- 跨城玩家在自己地图看到 A 城 NPC 出现（位置由 world-engine-a 实时同步）

### 6.5 跨城故障处理

| 场景 | 行为 |
|---|---|
| a2a-gateway 路由表里 city_b 离线 | 返回 F_011 `npc_unavailable_in_city_b`（HTTP 503）+ web UI 显示"该 NPC 暂时不可达" |
| city_b world-engine OOM | a2a-gateway 标记离线，跨城请求排队 30s 后失败 |
| mTLS 证书过期（> 90 天） | a2a-gateway 启动时校验，到期前 7 天触发自动轮换脚本 |
| Milvus 不可达 | 记忆召回降级到 PG short-term（player_session 表）top-K=3 |

### Step 1: login（双城玩家都登录）

### Step 2: walk（P_a 在 A 城走 3 步）

```go
assert.Equal(t, 3, count)
```

**断言**：3 步移动都成功；ws-gateway 推送 3 次 player_moved 事件。

### Step 3: 与 LLM-NPC 含记忆对话

```go
// Step 3a: 第一次对话（建立记忆）
http.Post(cityA+"/v1/npc/npc_a_wang_boss/talk",
  `{"text":"老板，今天有什么好吃的？"}`, jwt_a)
// 期望：王老板 LLM 回答 + 对话存入 Milvus `mem_a_wang_boss`

// Step 3b: 第二次对话（验证记忆）
http.Post(cityA+"/v1/npc/npc_a_wang_boss/talk",
  `{"text":"刚才那个红烧肉多少钱？"}`, jwt_a)
// 期望：王老板回答中含 "红烧肉" / "刚才" / "价格" 中至少 1 个关键词
```

**断言**：
- 王老板回答由 Claude 生成（非 1.0 固定台词）
- 第二次回答中含历史上下文关键词（≥ 1 个）—— **作为 binary 主判据**
- Milvus recall top-5 准确率 ≥ 70% 由离线评估脚本独立跑（不阻塞 binary），低于阈值在 §9.1 R9 触发降级

### Step 4: 跨城 NPC 对话（P_b 点 A 城 NPC grace_healer）

```go
http.Post(cityB+"/v1/npc/npc_a_grace_healer/talk",
  `{"text":"医生，我最近失眠。"}`, jwt_b)
// 流程：city_b → a2a-gateway 路由表 → city_a world-engine → city_a agent-os
```

**断言**：
- 跨城 HTTP 200 + 返回 grace_healer LLM 回复
- 总耗时 ≤ 1.5s（路由表查 + mTLS 握手 + gRPC 调用 + LLM 调用）
- a2a-gateway Prometheus 指标 `a2a_cross_city_routed_total` +1

### Step 5: 跨 NPC Saga 触发（3 NPC 协作剧本）

```go
// Step 5a: 正常路径
http.Post(cityA+"/v1/saga/trigger",
  `{"saga_id":"welcome_3npc","player_id":"demo_a"}`, jwt_a)
// 期望：saga-orchestrator 通过 Kafka 触发 3 个 saga-worker 任务
//   - saga_worker_a: 王老板 say greeting
//   - saga_worker_b: grace_healer say greeting
//   - saga_worker_c: 书店掌柜 say greeting
// 期望：3 NPC 5s 内全部 say 完成 + Saga 状态 = SUCCESS

// Step 5b: 失败路径（模拟 worker_c 失败触发补偿）
http.Post(cityA+"/v1/saga/trigger",
  `{"saga_id":"welcome_3npc_fail","player_id":"demo_a","force_fail":"worker_c"}`, jwt_a)
// 期望：worker_a/b 完成 → worker_c 失败触发补偿 → 回滚 worker_a/b
// 断言：saga_compensation_total{status="success"} +1
```

**断言**：
- 正常路径：3 NPC 5s 内全部 say 完成
- 失败路径：1 worker 失败 → Saga 状态 = COMPENSATED
- Saga 引擎补偿成功率（统计）≥ 95%

### 退出码

| 退出码 | 含义 |
|---|---|
| 0 | 5/5 全部通过 |
| 1 | 单步失败（打印失败 step + 期望 vs 实际） |
| 2 | 跨城连通失败（a2a-gateway 不可达 / 路由表空） |
| 3 | Milvus 不可达（步骤 3 降级到 PG short-term 也失败） |
| 4 | Saga worker 不响应（Kafka topic 无消息） |

### 跑法

```bash
MSYS_NO_PATHCONV=1 docker compose exec -T a2a-gateway /app/acceptance_2_0
# 期望：5/5 PASS in ~30s（不含 7 天稳定运行）
```

## 九、风险与降级

### 9.1 风险表

| # | 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|---|
| R1 | LLM 成本失控 | §10 5 条规则预算被击穿 | 中 | Sprint 13 Day 1 启用 chat_turns=6 强制收尾 + token caps + 监控告警（1.0 §10 规则文档已存在但**未启用**，2.0 LLM 轨道 Day 1 强制激活）；超预算 fallback 到本地 7B 模型 |
| R2 | Milvus 自托管运维复杂 | 阶段 1 推迟 | 高 | 用 Milvus standalone（单二进制）+ 预编译镜像；离线评估脚本 ≤ 2 周可跑通 |
| R3 | Saga 引擎 Kafka 引入 | 阶段 1 推迟 | 中 | 用 Kraft 模式（无 Zookeeper）+ docker compose 单节点；saga-orchestrator 用 idempotent 状态机 |
| R4 | mTLS 证书管理 | 跨城连通性掉 | 中 | 证书 90 天 + 启动时校验 + 到期前 7 天自动续签脚本 |
| R5 | 跨城网络延迟 > 1.5s P95 | acceptance_2_0 step 4 超时 | 低 | docker compose 同主机 + localhost 路由；真实跨城（K8s 阶段）才上 WireGuard |
| R6 | a2a-gateway 6772 LOC 现有代码与跨城设计冲突 | 重构 1-2 周 | 中 | 先做"路由表 + mTLS"增量补丁，不重写 InboxAdapter/OutboxAdapter；2 周不完成转降级 |
| R7 | NPC 表情/avatar 字段与 1.0 npc-templates schema 冲突 | 启动 yaml 报错 | 低 | 字段 optional + DEFAULT avatar；web 端 fallback 到 emoji |
| R8 | agent-os LLM 调用阻塞事件循环 | NPC move 事件静默丢失（参 1.0 move_scheduler bug） | 中 | LLM 调用走 `asyncio.create_task` 不 await；超时 5s 兜底默认台词 |
| R9 | Milvus recall top-5 准确率 < 70% | 验收 DoD 不过 | 中 | embedding 模型从 `all-MiniLM-L6-v2`（384 维）升级到 `bge-large-zh-v1.5`（1024 维）；标注集 ≥ 1000 条 |
| R10 | Saga 补偿成功率 < 95% | 验收 DoD 不过 | 中 | saga-worker 重试 3 次 + 指数退避；补偿任务 idempotent key |

### 9.2 降级矩阵（7 优先级）

如果 Sprint 13 (Week 4 末) 完成度 < 80%，按以下顺序降级：

| 优先级 | 降级动作 | 影响 | 触发判据 |
|---|---|---|---|
| P1 | **桶 2 P1 推迟** → 只启用 2 NPC（王老板 + grace_healer） | 演示 NPC 数量减半 | Sprint 13 Day 5 桶 2 P1 < 50% |
| P2 | **跨城范围缩小** → 只支持同城内 NPC 联邦 | acceptance_2_0 step 4 改为同城代理 | Sprint 14 集成周跨城连通性 < 100% |
| P3 | **记忆系统降级** → Milvus → pgvector | DoD §Milvus 召回准确率改成 pgvector 验收 | Sprint 13 Day 7 Milvus standalone 起不来 |
| P4 | **Saga 范围缩小** → 单 worker 串行 + 无补偿 | acceptance_2_0 step 5 改成单 NPC | Sprint 13 Day 8 Kafka 起不来 |
| P5 | **LLM 接入降级** → Claude Sonnet 直连（非 LiteLLM 抽象） | 多 Provider 切换延后 | Sprint 13 Day 3 LiteLLM 集成卡 |
| P6 | **5 步 binary 砍 1 步** → 砍 step 5 Saga（合并到 step 3） | 5/5 → 4/4 | Sprint 14 Day 3 step 5 失败 ≥ 3 次 |
| P7 | **7 天稳定验证缩到 3 天** | 风险高 + 1 | Sprint 15 Day 3 关键 bug 未修 |
