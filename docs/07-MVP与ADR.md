### MVP 验收标准（Definition of Done）
- 5 名 Beta 用户可在城市里自由行动。
- 至少 10 个 NPC 与用户 Agent 自主互动。
- openClaw 至少 1 个 Agent 接入并稳定运行 7 天。
- 至少完成 1 个剧本事件（城市欢迎仪式 + 大停电）。
- LLM 单日消耗 < $50。
- P95 接口延迟 < 500ms。

## 22. 技术栈选型 ADR（Architecture Decision Records）

### ADR-001：地图引擎选型

| 方案 | 优劣 |
|---|---|
| **MapLibre GL JS** ✅ | 开源、矢量瓦片、社区活跃、可定制。**推荐。** |
| Mapbox GL JS | 商业级体验好，但收费、有版权 |
| Leaflet | 简单但功能有限 |
| deck.gl | 大数据可视化强，但地图能力弱 |

**决策**：MVP 用 MapLibre GL JS；Phase 3 引入 CesiumJS 支持 3D 城市。

### ADR-002：后端语言选型

| 方案 | 优劣 |
|---|---|
| **Go + Python 混合** ✅ | Go 处理网关/世界引擎（高性能），Python 处理 Agent 逻辑（生态丰富）。**推荐。** |
| 纯 Python | 灵活但性能瓶颈 |
| 纯 Rust | 性能最佳但开发慢 |
| 纯 Node/TypeScript | 全栈一致但 LLM 生态弱 |

**决策**：Go（Gateway/World）+ Python（Agent OS）。

### ADR-003：Agent 决策框架

| 方案 | 优劣 |
|---|---|
| **自研 Agent OS** ✅ | 完全可控、定制化强。**推荐。** |
| LangGraph | 强大但偏重工作流 |
| AutoGen | 微软系，适合多 Agent 对话 |
| CrewAI | 简洁但扩展性一般 |

**决策**：核心决策循环自研；上层编排参考 LangGraph 思想。

### ADR-004：LLM 网关

| 方案 | 优劣 |
|---|---|
| **LiteLLM** ✅ | 多模型路由统一接口、易部署。**推荐。** |
| Portkey | 商业级、监控好 |
| OpenRouter | 第三方聚合 |

### ADR-005：实时通信

| 方案 | 优劣 |
|---|---|
| **WebSocket + Redis Pub/Sub** ✅ | 简单、可扩展。**推荐 MVP。** |
| MQTT | IoT 场景更适合 |
| Server-Sent Events | 单向流，适合低频 |

### ADR-006：关系图存储

| 方案 | 优劣 |
|---|---|
| **Neo4j** ✅ | 图查询语言 Cypher 强大、社区成熟。**推荐。** |
| Memgraph | 性能更好，社区较小 |
| PostgreSQL + JSONB | 简单但查询性能差 |

### ADR-007：向量库

| 方案 | 优劣 |
|---|---|
| **Milvus** ✅ | 分布式、生产级。**推荐。** |
| Qdrant | Rust 写、性能好 |
| Weaviate | 内置 RAG 友好 |
| pgvector | 简单但规模受限 |

## 23. 商业模式与社区策略

### 23.1 三层付费模式

| 层级 | 目标用户 | 收费模式 | 主要权益 |
|---|---|---|---|
| **Free** | 普通用户 | 免费 | 1 个 Agent、基础地图、基础 NPC 互动 |
| **Pro（¥29/月）** | 重度玩家 | 订阅 | 多 Agent、私域空间、技能加速、VIP NPC 好感 |
| **Enterprise（定制）** | 企业 / 开发者 | API 调用费 | A2A 接入、品牌定制、数据分析、专属客服 |

### 23.2 第三方 Agent 接入费
- **审核费**：一次性 ¥1000，用于 Agent Card 审核与安全审计。
- **能力调用费**：按 API 调用次数 / Token 数计费。
- **白标服务**：企业可付费定制城市主题。

### 23.3 收入模式预估（保守）

| 收入项 | 12 个月内预估 |
|---|---|
| Pro 订阅（1000 用户 × ¥29/月 × 6 月平均） | ¥174,000 |
| 第三方接入费（20 家 × ¥1000） | ¥20,000 |
| 能力调用费 | ¥50,000 |
| 企业定制 | ¥200,000 |
| **合计** | **¥444,000** |

### 23.4 数据策略
- **用户数据所有权**：用户随时可导出自己的 Agent 全部数据。
- **数据匿名化**：用于训练的数据需经用户同意并匿名化。
- **数据不出境**：国内用户数据存储于国内服务器。

### 23.5 社区策略

| 社区内容 | 形式 | 激励 |
|---|---|---|
| NPC 人设创作 | UGC 平台 | 优秀人设被官方采纳 + 现金奖励 |
| 城市副本设计 | UGC 工具 | 玩家投票最受欢迎副本 + 收入分成 |
| 剧情故事 | 短篇/剧本 | 官方征稿，稿费 + 署名 |
| Mod 与插件 | 开放 SDK | 热门 Mod 获得官方推广 |
| 第三方 Agent 应用 | A2A 应用商店 | 收入 70% 归开发者 |

### 23.6 开源策略
- **核心协议开源**：A2A v1.0、Agent Card Schema、数据格式（CC BY 4.0）。
- **参考实现开源**：Agent OS SDK、Gateway 参考实现（Apache 2.0）。
- **城市数据闭源**：具体城市内容、用户数据、商业逻辑不开放。
- **社区贡献**：通过 GitHub 接受 PR，活跃贡献者可加入"城市议会"。

### 21.8 MVP 风险评估与应对预案

| 风险 | 概率 | 影响 | 应对预案 |

| 跨 Tile 状态不一致 | 低 | 高 | §35 跨 Tile 一致性方案 + 分布式锁 |
| 数据丢失 | 低 | 致命 | PG WAL 流复制 + S3 每日全量 |

- **日期**: YYYY-MM-DD

## 背景与驱动 (Context & Drivers)

我们选择了选项 X，因为...

## 后果 (Consequences)
### 正面
- ...

### 负面
- ...

- ...

### 22.9 ADR 决策链（连锁决策）

> 大决策不是孤立的，链式记录可以看清"决策依赖"。

```
ADR-001 地图引擎    →  ADR-007 地图服务部署方式
                  →  ADR-008 前端框架
                  →  ADR-015 数据传输协议

ADR-002 后端语言    →  ADR-009 ORM 选型
                  →  ADR-010 鉴权实现
                  →  ADR-016 部署镜像构建

ADR-003 Agent 决策  →  ADR-011 LLM Provider 多路
                  →  ADR-012 决策缓存策略
                  →  ADR-013 反思 Prompt 设计

ADR-004 LLM 网关   →  ADR-011 / ADR-014 配额体系
```

**ADR 决策链维护规则**：
- 每个 ADR 必须列出 `depends_on` 与 `blocks`。
- 决策链变更需在 ADR 评审会上同步公示。
- 季度复盘："哪个 ADR 后果被验证？哪个被推翻？"

### 22.10 ADR 评审会议节奏

| 节奏 | 内容 | 参与者 |
|---|---|---|
| **每周 ADR Sync**（30min） | 新 ADR 评审 + 老 ADR 状态更新 | Tech Lead + 全工程师 |
| **每月 ADR Review**（1h） | 决策链复盘 + 推翻/补充 | Tech Lead + 产品负责人 |
| **季度 ADR Audit**（2h） | 全部 ADR 回头看 | 管理层 + 工程团队 |

**ADR 数量控制**：
- 单 Sprint 新增 ADR ≤ 5 个（强制让团队克制"技术狂热"）。
- Deprecated ADR 必须明确替代方案（Superseded by ADR-XXX）。

### 23.8 监管合规

#### 23.8.1 个人信息保护（PIPL / GDPR）

| 要求 | 实现 |
|---|---|
| 用户数据可导出 | `GET /users/me/export` 返回 JSON |
| 用户可删除（被遗忘权） | `DELETE /users/me` 软删 → 90 天硬删 |
| 数据最小化 | 用户表只存必要字段（email + display_name + tier） |
| 同意书 | 注册时勾选"数据使用同意书"，可撤回 |
| 数据本地化 | 国内用户数据不出境（分区） |

#### 23.8.2 AI 生成内容标识

- 所有 NPC 输出强制带 `[AI 生成]` 前缀（合规）。
- 玩家创作的内容必须有水印 + 自愿声明。
- 每 100 条 NPC 输出抽样人工审核（每月）。

#### 23.8.3 未成年人保护

- 16 岁以下用户禁用付费功能。
- 夜间 22:00-8:00 强制 NPC 减少负面情绪输出。
- 家长可远程 `GET /children/:id/usage` 查看时长。

#### 23.8.4 反洗钱（AML）/ 反恐融资（CTF）

- 资金类操作（>500 信用/天）需 KYC。
- 可疑模式检测：突然高频交易 / 拆分小额 / 跨境转账。
- 与第三方反欺诈服务集成（Sift / 阿里云风险识别）。

### 23.9 数据本地化与跨境

| 数据类型 | 存储位置 | 跨境策略 |
|---|---|---|
| 国内用户 PII | 国内阿里云 | 不出境 |
| 海外用户 PII | AWS 新加坡 / 法兰克福 | 区域自治 |
| NPC 配置 / 城市内容 | 全球 CDN | 全球可访问 |
| 联邦 LLM 调用 | 就近 Provider | 优先本地 LLM |

**Failover**：海外 Provider 故障 5min 内自动切回国内 LLM（鸿蒙商用大模型等），降级不中断。

### 23.10 退出策略与退出成本

| 退出场景 | 关键资产 | 退出成本 | 用户影响 |
|---|---|---|---|
| **被收购** | 用户数据 + Agent Card 协议 + 团队 | 中（3 个月） | 中（迁移工具） |
| **倒闭** | 数据库导出 + 服务关停 | 高（6 个月） | 高（数据可导出） |
| **开源分叉** | 协议 + SDK | 低（已开源部分） | 低（社区接手） |
| **转做 SaaS** | 基础设施 + 鉴权 + LLM 网关 | 低（部分可复用） | 低（同产品） |
| **被监管叫停** | 需保留审计日志 5 年 | 高 | 未知 |

**降低退出成本的 5 项原则**：
1. 核心协议必须开源（§23.6 已有）。
2. 用户数据格式标准化（OpenAPI 充分覆盖 §18.11）。
3. 不锁定单一 LLM Provider（§09.34 多路复用）。
4. 关键决策进 ADR 文档（§22.8）。
5. 数据 30 天内可完整导出。
