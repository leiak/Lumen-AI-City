**关键设计**：
- `packages/` 内的 proto / schema 是**契约之源**，所有服务强类型通信。

- 单服务内部走函数调用，不用 HTTP。
- `packages/` 与 apps / web 解耦，独立语义版本。

### A.3 跨服务调用与契约

| 调用方向 | 协议 | 鉴权 | 失败处理 |
|---|---|---|---|
| 前端 → Gateway | REST + WebSocket | JWT / API Key | 重试（§18.9.2） |
| Gateway → 服务 | gRPC | mTLS（服务间） | 自动重试 + circuit breaker |
| 服务内 → DB | 各 DB 驱动 | DB 凭据 | 连接池 + 超时 |
| 服务 → LLM | HTTPS + LiteLLM | API Key | 多 Provider fallback（§34.4） |
| 服务 → Kafka | Producer / Consumer | SASL | DLQ |
| 联邦 → A2A Gateway | WebSocket + JSON | ed25519 / mTLS | 重连 + 重发 |

## §B 5 个核心实现模式（最关键的）

### B.1 模式 ①：Tick + Event 混合驱动

**问题**：纯事件驱动在 1 万 NPC 时被洪流冲垮，纯 Tick 又让 NPC 反应太迟钝。

```python
class AgentRuntime:
    def __init__(self, agent_id: UUID):
        self.tick_interval = 5.0      # 配置项
        self.high_pri_queue = asyncio.Queue()  # 紧急事件（玩家互动等）

    async def run(self):
        while not self._stop:
            batch = await self._gather_batch()        # tick 期间累积
            urgent = await self._drain_high_priority()# 立即处理（不等 tick）

            if not batch and not urgent:
                await asyncio.sleep(self.tick_interval)
                continue

            decision = await self.planner.decide(
                batched_percepts=batch,
                urgent_percepts=urgent,
                last_decision=self.last_decision    # 用于去重
            )
            await self.actor.execute(decision)        # Saga 包裹
            await asyncio.sleep(self.tick_interval)
```

**关键**：
- 同 tick 内的多个 percept **合并**为一次 LLM 调用（省 token）。
- `urgent` 队列是"打断式"——不等 tick。
- Tick 间隔可动态调（§19.9.3）：CBD 2s、郊区 10s、节日期间 -50%。
- 高优事件需带 `_reason`，避免被刷屏。

- 单元测试：录制决策 → 改代码 → 重放验证无回归。
- "如果当时 NPC 收到 X，会怎样？"——这是 NPC 行为调试的核心工具。

### B.3 模式 ③：LOD 三档决策降级

| LOD | 玩家可见状态 | 决策方式 | 实现 |
|---|---|---|---|
| **L0** 背景板 | 视野内但不互动 | 行为树（无 LLM） | 每 5s tick |
| **L1** 互动 NPC | 进入 50m | 行为树 + LLM 升级 | 行为树默认、特定动作升级 |
| **L2** 主角 | 玩家主动选中 | 全程 LLM（每 5s） | Sonnet 为主 |

**关键代码**：

```python
class BehaviorTreeAgent:
    def decide(self, percept):
        # 行为树先尝试
        action = self.bt.tick(percept)

        # 玩家互动 → LLM 升级
        if percept.contains("player_dialogue"):
            return self.llm_fallback(percept, prior=action)

        # 行为树无匹配 → LLM 兜底
        if action is None:
            return self.llm_fallback(percept)

        return action
```

**实测**：LOD 化后 LLM 调用整体下降 96%，NPC 多样性评分仅牺牲 0.3/10（见 §49.6）。

### B.4 模式 ④：三层记忆的 RAG 写入与检索

```python
class MemoryPipeline:
    async def on_perception(self, agent_id, percept):
        # 1. 感官缓存（Redis，TTL 5min，最多 10 条）
        await redis.lpush(f"sens:{agent_id}", percept.json(), max=10, ttl=300)

        # 2. 情节记忆（异步，先打 importance 分）
        importance = await self.importance_scorer.score(percept)
        if importance >= 0.3:
            embedding = await self.embed(percept.content)
            await milvus.insert("agent_memories", {
                "agent_id":     agent_id,
                "content":      percept.content,
                "embedding":    embedding,
                "importance":   importance,
                "created_at":   now_ms(),
            })

    async def recall(self, agent_id, query, k=10):
        sensory  = redis.lrange(f"sens:{agent_id}", 0, -1)         # 廉价、快
        episodic = await milvus.search("agent_memories",            # 远期
            data=[await self.embed(query)],
            filter=f"agent_id == '{agent_id}' and importance > 0.3",
            limit=k,
        )
        semantic = await self.semantic_search(query)                 # 长期偏好
        return await rerank_and_summarize(sensory, episodic, semantic)
```

**为什么是三层而不是一层**？
- 感官层（Redis）= 廉价、低延迟、最近的"上下文窗口"。
- 情节层（Milvus）= "我过去做什么"，按 importance 衰减。
- 语义层（Neo4j）= "我是什么样的人"，长期性格 / 偏好。

### B.5 模式 ⑤：Saga 跨服务事务

```python
class MoveItemSaga:
    steps = [
        ("validate",         ItemService,     "validate_ownership"),
        ("lock_inventory",   InventoryService,"lock"),
        ("transfer_credit",  LedgerService,   "transfer"),
        ("unlock_inventory", InventoryService,"unlock"),
        ("commit",           ItemService,     "commit"),
    ]
    compensations = {
        "lock_inventory":   "unlock",
        "transfer_credit":  "reverse_transfer",
    }

    async def execute(self, payload):
        ctx = SagaContext(payload)
        for name, service, action in self.steps:
            try:
                await getattr(service, action)(ctx)
                ctx.completed.append(name)
            except Exception as e:
                await self._compensate(ctx, failed=name, error=e)
                raise SagaAborted(name, e)

    async def _compensate(self, ctx, failed, error):
        for name in reversed(ctx.completed):
            comp = self.compensations.get(name)
            if comp:
                try:
                    await getattr(self.services[name], comp)(ctx)
                except Exception as ce:
                    await self.dlq.push(name, ce)  # 进 DLQ 人工处理
```

**核心**：
- **Orchestration** 而非 Choreography：Saga 集中调度，方便调试和补偿。
- 每个 step 都带 `idempotency_key`，可重试不重复扣款。
- DLQ + 告警：补偿失败必须进 DLQ，**不能"吞掉"**。

## §C 7 种玩家玩法模式

> 这是 AI 城邦与一般游戏最大的不同——玩家用什么姿势玩由玩家自己选，我们提供的是"**玩法矩阵**"而非单条玩法路径。

### C.1 模式 ①：🎒 散步访客（Solo Casual）

| 维度 | 内容 |
|---|---|
| 典型用户 | 地铁上看一眼、合上手机的人 |
| 典型会话 | 1-15 分钟 / 次，每周 2-3 次 |
| 客户端 | iOS / Android App（轻量） |
| 数据范围 | 玩家视野 1 圈 + 当前对话对象 + 2-3 个 UI 卡片 |
| 主要 API | `GET /worlds/:id/snapshot?visible_only=1`、`GET /agents/me/summary` |

**关键技术**：
- **决策预计算**：玩家未连入时 NPC 已周期性做完所有决策，玩家一连入直接看到"最近 10 分钟发生了什么"。
- **离线消息汇总**："老李昨天找你聊过天，要回吗？"—— 后台定期 push。
- **Push 通知引擎**：APNs / FCM，智能触发（不打扰时段）。
- **轻量渲染**：客户端 80% 走本地缓存，仅 5% 网络流量。

### C.2 模式 ②：🧑‍🤝‍🧑 常住居民（Solo Engaged）

| 维度 | 内容 |
|---|---|
| 典型用户 | 大学生、退休人士、二次元 / 模拟经营爱好者 |
| 典型会话 | 1-3 小时 / 次，每周 5+ 次 |
| 客户端 | Web 端（Next.js + MapLibre 2.5D） |
| 数据范围 | 完整 LOD=L2 决策链可见 |
| 主要 API | 完整 §18 REST + WS，决策链 `GET /agents/:id/decisions?trace_id=` |

**关键技术**：
- **持久身份**：玩家有 avatar、装备、好友、社团、剧情进度。
- **玩家状态机**：在家 / 出门 / 工作，NPC 据此找上门。
- **节日倒计时 + 任务追踪** 钉在 UI 顶栏。
- 跨设备同步：基于 JWT，state 走服务端。

### C.3 模式 ③：📺 旁观者（Read-only Spectator）

| 维度 | 内容 |
|---|---|
| 典型用户 | 研究者、AI 圈观察者、媒体报道 |
| 典型会话 | 5-30 分钟 / 次，随机频率 |
| 客户端 | 公开仪表盘网站（无需注册） |
| 数据范围 | NPC 间通信 + 公区域对话（隐私过滤后） |
| 主要 API | `GET /public/world/feed`、`GET /agents/:id/stream`（SSE） |

**关键技术**：
- **旁路流**（§E.4）：写路径是"内部 NPC 通信"，旁路是"公开叙事视图"——双轨制。
- **隐私过滤**：玩家 PII 自动识别 + 替换。
- **故事性评分**：用 LLM 给 NPC 互动打分，前 1% 推到旁观者看板。
- 内容审计：每月抽样 100 起事件人工核查。

### C.4 模式 ④：🎭 故事模式（Story Campaign）

| 维度 | 内容 |
|---|---|
| 典型用户 | 剧情党、RPG 玩家 |
| 典型会话 | 3-8 小时通关一章，每月 1 章 |
| 客户端 | Web 端 + 进度引导 |
| 数据范围 | 章节进度 + 已解锁剧情 + 决策树 |
| 主要 API | `GET /story/:id/progress`、`POST /story/:id/save` |

**关键技术**：
- **剧本引擎是状态机**（已发生的事不会改），不是规则系统。
- 触发条件用 **DSL**（§E.2）。
- 决策可存档 / 加载（与 §19.14 决策回放共用机制）。
- **章节式收费**：基础章免费，扩展章 $4.99。

### C.5 模式 ⑤：🛠 创作者（Creator / Modder）

| 维度 | 内容 |
|---|---|
| 典型用户 | 同人作者、Roblox / Minecraft 创作者 |
| 典型会话 | 创作 10h + 持续运营 1h / 周 |
| 客户端 | 创作者后台 + 可视化编辑器（§E.1） |
| 数据范围 | 自建 NPC / 场景 / 剧本，跑在沙箱 namespace |
| 主要 API | `POST /creator/:id/sandbox/run`、`GET /creator/:id/marketplace` |

**关键技术**：
- **沙箱租户**：创作者内容跑在独立 namespace，token / credit 配额独立计费。
- **可视化编辑器**：§E.1 详细描述，拖拽式行为树 + 剧本 DSL。
- **审核双层**：LLM + 人工，与 §36 一致。
- **版税系统**：创作者的 NPC / 剧本被玩家使用，按比例分红（与 §23 商业模式对齐）。

### C.6 模式 ⑥：💻 开发者（Programmatic）

| 维度 | 内容 |
|---|---|
| 典型用户 | AI Agent 研究者、第三方公司 |
| 典型会话 | 集成 1 周 + 持续迭代 |
| 客户端 | A2A v0.1（§20）+ 多语言 SDK（§20.17） |
| 数据范围 | 联邦身份下的 Agent / NPC / Region |
| 主要 API | A2A Gateway + `/federation/register` |

**Tier 分级**：
| Tier | 接入方式 | 配额 | 限制 |
|---|---|---|---|
| **测试** | API Key 即开通 | 100 NPC / 账号 + 1000 LLM token / 天 | 强制水印 |
| **企业** | 白名单 mTLS | 自定义 rate limit | SLA 99.9% |
| **学术** | 邮件申请 | 高 token 配额 | call 强制"研究水印" |

**关键技术**：
- **Trace 透明**：开发者可看到自己 Agent 的 5 类决策日志。
- **配额独立计费**：与其他模式隔离。
- **审核快通道**：开发者 Tier 上传的内容走 §28 自动化审核。

### C.7 模式 ⑦：🌐 联邦漫游（Federation）

| 维度 | 内容 |
|---|---|
| 典型用户 | 安装了多个 AI 城邦工具的重度用户 |
| 典型会话 | 跨平台游玩、漫游 |
| 客户端 | 同模式 ①~⑥，但身份是"联邦" |
| 数据范围 | 跨城访问，A 城 NPC 可邀请到 B 城 |
| 主要 API | A2A Adapter（§20.14） |

**关键技术**：
- **联邦身份映射**（§E.5）：每个 NPC / Player 有全局 UUID + 各城分片 ID。
- **跨城消息延迟**：RPC 默认 100ms 容忍度，P99 = 200ms。
- **跨城经济**：A 城 credit 到 B 城汇率 = 1:1，但有 5% 联邦税（防洗钱）。
- **跨城合规**：联邦协议遵守 §23.8 监管。

## §D 上线节奏的工程化拆解

按"6-8 周 MVP"（§30）来看，落地分 3 阶段：

### D.1 阶段 A：MVP 单模式上线（6-8 周）

**只做模式 ① + ②（散步 + 常住）**：

- 1 个城市 = 1 个 region = 5×5 tiles
- 10 个样板 NPC（§15.2）
- Web 客户端（移动端后做）
- 4 个节日（§16.4）
- **不开放**：联邦 / 创作者 / 旁观者
- **延期**：语音 / VR / 3D model（§30.8 反向验证）

**验收**：24h 压测零崩溃 + 单 NPC 决策 < 200ms。

### D.2 阶段 B：单城稳定版（9-14 周）

- 扩到 50×50 tiles + 200 NPC
- 加入**模式 ③ 旁观者**（公开仪表盘）
- 加入**模式 ④ 故事模式**（章节购买）
- 移动端 Beta

```python
class BTCompiler:
    def compile(self, bt_json: dict) -> Callable:
        node_funcs = {}
        # 1. 拓扑排序
        order = topological_sort(bt_json["nodes"], bt_json["root_node_id"])
        # 2. 每节点编译成 Python 函数
        for nid in order:
            node_funcs[nid] = self._compile_node(nid, bt_json["nodes"][nid], node_funcs)
        return node_funcs[bt_json["root_node_id"]]

    def _compile_node(self, nid, node, funcs):
        if node["type"] == "Selector":
            children = [funcs[c] for c in node["children"]]
            return lambda ctx: any(c(ctx) for c in children)
        elif node["type"] == "Action":
            verb = node["verb"]
            return lambda ctx: world_engine.execute(verb, node["params"], ctx)
        # ... 其它类型
```

### E.2 Saga DSL（剧本触发条件语法）

#### E.2.1 目标

让**剧情创作者**用声明式语法定义"事件触发条件"，让 Saga 引擎自动触发 / 推进 / 回滚。

#### E.2.2 DSL 设计

**核心 4 类语句**：

```yaml
# 1. 触发条件（trigger）
- on: visit(tile_cbd)
  when: has(item_key) && day >= 14
  do: story_chapter("cbd_mystery", stage="start")

# 2. 顺序步骤（steps）
- saga: move_item
  steps:
    - validate
    - lock_inventory
    - transfer_credit
    - unlock_inventory
    - commit

# 3. 补偿动作（compensation）
  on_fail_of: transfer_credit
  compensate:
    - refund: from=buyer, amount=price

# 4. 副作用钩子（hook）
- on: npc.dialogue_end
  if: npc_id == "npc_ayi"
  do: append_memo(quality_score=llm_score(content))
```

#### E.2.3 语法规则（详细 EBNF）

```
saga       := 'saga' IDENT '{' step+ '}'
step       := 'on' condition 'do' action
           |  'saga' IDENT
           |  'compensate' action
condition  := disjunction
disjunction:= conjunction ('||' conjunction)*
conjunction:= atom ('&&' atom)*
atom       := function_call | comparison | '(' condition ')'
function_call := IDENT '(' arglist? ')'
comparison := value ( '==' | '!=' | '<' | '<=' | '>' | '>=' ) value
value      := STRING | NUMBER | IDENT | '[' arglist ']'
action     := IDENT ( '(' arglist ')' )?
arglist    := arg (',' arg)*
arg        := STRING | NUMBER | IDENT | IDENT ':' value
```

#### E.2.4 内置函数（80+ 个）

| 分类 | 函数 |
|---|---|
| 时间 | `day()`, `hour()`, `weekday()`, `season()` |
| 位置 | `visit(tile_id)`, `near(tile_id, radius)`, `current_tile()` |
| 物品 | `has(item_id, qty)`, `items()`, `inventory_full()` |
| 关系 | `relationship(agent_b) >= 60`, `met(agent_b)` |
| 玩家 | `player.tier()`, `player.reputation()`, `player.active()` |
| NPC | `npc.status()`, `npc.is_alive()`, `npc.emotion.joy() > 0.6` |
| 货币 | `balance() >= N`, `today_spent()`, `can_afford(price)` |
| Saga | `saga_state(name) == "completed"`, `saga_failed(name)` |

```python
class BypassFilter:
    """双轨制：内部 → 公开"""

    async def process(self, raw_event: dict) -> dict | None:
        # 1. 类型过滤：仅部分事件类型出公开
        if raw_event["type"] not in ALLOWED_PUBLIC_TYPES:
            return None

        # 2. 玩家 PII 过滤
        event = self._strip_player_pii(raw_event)

        # 3. 故事性评分（用 LLM）
        score = await self._narrative_score(event)
        if score < 0.6:
            return None

        # 4. 频率过滤（避免刷屏）
        if await self._is_flooding(event):
            return None

        return event

    def _strip_player_pii(self, event):
        """玩家 ID、昵称、IP、发言全部置为 [Anonymous]"""
        if "player" in event:
            event["player"] = "[Anonymous]"
        if "from_agent" in event:
            if is_player(event["from_agent"]):
                event["from_agent"] = "[Player]"
        return event
```

### E.6 客户端预测 + 服务端协调（移动端网络抖动容忍）

#### E.6.1 目标

移动网络**平均 200ms 抖动**、**3% 丢包率**情况下，玩家操作仍流畅。

#### E.6.2 三原则

1. **乐观更新**：玩家点击 → 立即 UI 反馈（不等服务端）。
2. **请求队列**：所有动作进入 outbox 队列，逐个按顺序发。
3. **服务端权威**：服务端结果回包时校正状态，必要时回滚。

#### E.6.3 客户端 outbox 实现

```typescript
class Outbox {
  private queue: OutboxItem[] = [];

  async enqueue(action: Action): Promise<OptimisticUpdate> {
    const id = crypto.randomUUID();
    const item = { id, action, ts: Date.now(), retries: 0 };
    this.queue.push(item);

    // 1. 立即更新 UI（乐观）
    this.applyOptimistic(item);

    // 2. 异步发送到服务端
    this.flush().catch(console.warn);

    return new OptimisticUpdate(id);
  }

  async flush() {
    while (this.queue.length > 0) {
      const item = this.queue[0];
      try {
        const result = await this.send(item);
        this.confirmOptimistic(item, result);
        this.queue.shift();
      } catch (e) {
        if (e instanceof ConflictError) {
          // 服务端拒绝：回滚乐观更新
          this.rollbackOptimistic(item);
          this.queue.shift();
          throw e;
        }
        item.retries++;
        if (item.retries > 3) {
          // 进死信
          await this.dlq.push(item);
          this.queue.shift();
        }
      }
    }
  }
}
```
