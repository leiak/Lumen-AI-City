# 1.0 演示脚本 — 3 分钟跑通 MVP 闭环

> **目标**：3 分钟内让 stakeholder **眼睛看到 + 耳朵听到** 一个完整闭环：
> 玩家进 3×3 城市 → 看到 1 个 NPC 走动 → 走近时 NPC 主动打招呼 → 玩家回复 → NPC 返下一句。
>
> **观众**：产品 / 业务 / 投资方（**非工程师**）。术语降到最低：
> - 不说 "WebSocket" "Redis pub/sub" "gRPC" "BT" "Saga"
> - 只说 "AI 城邦" "NPC" "玩家" "对话" "AI 公民"
>
> **前置条件**：见 §零 Pre-demo Checklist（演示前 5 分钟必过）

---

## 零、Pre-demo Checklist（演示前 5 分钟）

> 这 5 项任何一项没过，**演示不开始**（避免 stakeholder 看 demo 时翻车）

```bash
# 1. 8 容器 healthy
cd /d/work-ai/0401-town/ai-city
docker compose ps
# 预期：8 个 service 都显示 "Up (healthy)" 或 "Up"
# 7 + 1 = postgres / redis / world-engine / api-gateway / ws-gateway / web / a2a-gateway / agent-os

# 2. demo 玩家存在（pgcrypto bcrypt 种子）
docker compose exec -T postgres psql -U aicity -d aicity -tAc "select username from player;"
# 预期：demo / admin（两行）

# 3. 重启 agent-os（清 welcome set + 加载最新 wang_boss.yaml）
docker compose restart agent-os
sleep 3
docker compose logs --tail=20 agent-os | grep -E "loaded npc|listening"
# 预期：loaded npc templates count=1, listening on ...

# 4. 王老板 enabled
docker compose exec -T agent-os cat /app/packages/npc-templates/wang_boss.yaml | grep -E "^enabled"
# 预期：enabled: true
# （其他 4 NPC 应该 enabled: false，1.0 只演王老板）

# 5. 浏览器预热（提前 30s 开好）
# Chrome 标签：localhost:3000 (login)  ← 主屏
# Chrome 标签：localhost:3000/city      ← 第二屏（演示多 tab 同步，可选）
# 终端 1：docker compose logs -f agent-os  ← 后台日志（出问题时给观众看证据）
# 终端 2：当前 shell                     ← 跑 acceptance_1_0 用
```

**应急**：任一项不过 → 喊停 → 修 → 不要带着破的 demo 跑下去。

## 三、Stakeholder 可能问的 Q&A（提前准备）

### Q1："这是不是写死的对话？不是 AI 吧？"
> **A**："对，1.0 是预设回复树，证明 AI 公民这个体验形式能跑通。
> 2.0 接 LLM 后，同样的对话框架可以接真 AI 生成——体验形态不变，只是底层从查表变成推理。"

### Q2："为什么只有 1 个 NPC？"
> **A**："1.0 切到最小闭环，先证明 1 个能跑。NPC 数量是数据问题，引擎已经能跑——加 1 个 NPC 加 1 个 yaml 而已。
> 2.0 会扩到 6 NPC + 多 NPC 互动 + NPC 寻路。"

### Q3："那个 NPC 是不是会乱走？"
> **A**："对，NPC 会按 BT（行为树）自己走动——目前是按 schedule 走（10 点开门 / 22 点打烊）。
> demo 看到的是'在 tile_0_0 站着'，因为 demo 时段是早上。"

### Q4："多 tab 同步是什么原理？"
> **A**："WebSocket 推送。一个 tab 移动，所有 tab 都实时收到。
> stakeholder 可以打开 2 个浏览器窗口试。"

### Q5："这个能商业化吗？什么时候上线？"
> **A**："1.0 是内部 demo 形态，不能直接上线。商业化要等 2.0——加 LLM + 创作者市场 + 合规。
> 1.0 跑通后我们内部可以拿 demo 给客户看'形态是什么样的'，但交付要 2.0 起。"

### Q6："对比其他游戏有什么差异？"
> **A**："**核心差异**：NPC 是 AI 公民，不是脚本。玩家走近会主动互动——这是传统 RPG 没有的。
> 形式上是 2.5D 俯视城邦，本质是 AI 公民持续运行的世界。"

### Q7："为什么不做 LLM？不是更智能吗？"
> **A**："LLM 成本高 + 不可控 + 需要合规。1.0 用 BT + 脚本化选择树证明体验形态成立，
> 2.0 接 LLM 时体验不变——只是 NPC 说的话从'预设'变成'生成'。"

### Q8："代码复杂度？团队规模？"
> **A**："1 个工程师 + 1 个产品 + 半个设计，4 周做完 1.0。当前代码 ~16K LOC，加 1.0 后预估 +3K。
> 团队规模不放大，工程效率主要靠 1.0 切得够小。"

## 四、应急（演示中真出问题）

### 应急 1：王老板不主动打招呼（1:00 没气泡）

**症状**：玩家走回 tile_0_0 后 NPCDialog 没自动弹。

**现场处理**（30 秒内）：
```bash
# 看 agent-os 日志
docker compose logs --tail=50 agent-os | grep -E "player_moved|trigger|welcome"
# 预期：看到 "player demo entered tile_0_0" + "triggering welcome storyline"
# 实际：无 → 玩家 listener 没工作 / 王老板 enabled false

# 修复 A：重启 agent-os
docker compose restart agent-os
sleep 3
# 让玩家再走开再走回

# 修复 B：手动触发（应急，最后手段）
docker compose exec -T agent-os python -c "
from agent_os.player_listener import PlayerListener
from agent_os.storyline import trigger_storyline
trigger_storyline('npc_wang_boss_001', 'welcome')
"
# 玩家端应该 5s 内看到气泡
```

**讲台话术**：
> "Demo 容器刚跑完别的测试，状态没完全清。我重启下 agent-os。"

### 应急 2：第二 tab 不同步（2:30 没看到其他 tab 移动）

**症状**：开第二个 tab，第二 tab 不显示第一 tab 的玩家移动。

**现场处理**（20 秒内）：
```bash
# 看 ws-gateway 日志
docker compose logs --tail=30 ws-gateway | grep -E "broadcast|fanout|delivered"
# 预期：看到 player_moved envelope 投递数 = N (clients)

# 修复：硬刷新第二 tab（Ctrl+Shift+R）
# 如果还不通 → ws-gateway 重启
docker compose restart ws-gateway
sleep 5
# 重新打开第二 tab
```

**讲台话术**：
> "WebSocket 长连接偶发需要重连——刷一下就好了。"

### 应急 3：acceptance_1_0 失败（2:55 没看到 5/5）

**症状**：二进制退出码非 0，输出 hint 表。

**现场处理**：
```bash
# 看完整 hint 输出
docker compose exec -T a2a-gateway /app/acceptance_1_0 -verbose 2>&1 | tail -100

# 按 hint 表诊断（参 docs/1.0-acceptance-design.md §五）
# 大概率是 step 4/5（NPC say 没触发或 reply 没回）→ §四 应急 1 修
```

**讲台话术**（如果 30 秒内修不好）：
> "1.0 demo 还在迭代，验收 binary 是开发工具不是产品功能。
> 我已经现场展示了完整的玩家↔NPC 互动闭环——这就是 1.0 的核心。
> 录屏版本是稳定的，所有节点都跑通过的。"

### 应急 4：浏览器卡死（任何时间）

**现场处理**：直接换备份浏览器（提前准备）。
> "切个浏览器继续。"

## 八、附录：术语映射（演示中不说的内部词）

| 内部词 | stakeholder 词 | 为什么不说 |
|---|---|---|
| WebSocket / WS 推送 | "实时同步" | 容易引出技术讨论 |

| gRPC / MoveEntity | "后端 API" | 不重要 |

| LLM | "AI 生成" | 1.0 没用，避免误导 |
| accept binary | "自动化验收" | "binary" 听起来太技术 |
| WS_RECONNECTED_EVENT | "断线重连" | 不主动提 |
| Hub 单 goroutine | "消息分发" | 内部实现 |

## 九、附录：成功判据

演示成功 = stakeholder 走出会议室时**能向同事复述**这三件事：

1. **"玩家走进城邦，NPC 会主动打招呼。"**（NPC 主动 say，1.0 核心）
2. **"玩家可以选话题，NPC 接着聊。"**（多轮对话，行为树）
3. **"5 步自动化验收都过了。"**（工程可信度）

如果 stakeholder 只能记住一件事 → **第 1 件**（NPC 主动 say 是 1.0 最差异化）。
