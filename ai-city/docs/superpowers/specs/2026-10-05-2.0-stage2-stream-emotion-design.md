# 2.0 阶段 2 — LLM 流式 + emotion 表情（Sub-spec A）

> **Status:** Draft（待 user review）
> **Date:** 2026-10-05
> **Branch:** main（继承 2.0 阶段 1 GA）
> **Reference:** `docs/2.0-ROADMAP.md` §阶段 2 + ADR-0007

## Summary

在 2.0 阶段 1 LLM-NPC（batch 模式）基础上，把 5 个 enabled NPC 的对话从「等整段返回」升级为「**句子级流式推送 + 句末 emotion 表情**」，让玩家实时看到 NPC 一句一句说出来，每句末尾头像叠加 8 类表情之一。

**核心变更**：
- agent-os `dispatcher.say()` → `dispatcher.say_stream()`（LLM 真流式 + 切句 + emotion tag 解析）
- Redis 新频道 `aicity:npc:say_stream`（节拍包发布）
- ws-gateway 多频道订阅（**沿用 stage1**，仅配置新增）
- web NPCDialog 改造为**逐句渲染** + 8 类表情动画
- 新 binary `acceptance_2_1`（5/5 验证）

**不在范围**：BT 编辑器 v2 / Saga DSL 可视化 / 跨城 NPC 流式（各自独立 sub-spec）。

## §2 数据流 / 节拍包格式

### 2.1 节拍包 schema

```json
{
  "type": "npc_say_stream",
  "npc_id": "npc_wang_boss_001",
  "session_id": "sess-abc123",      // 玩家↔NPC 对话 session
  "sentence_idx": 0,                // 0-based 句子索引
  "text": "来了您嘞！",             // 单句文本
  "emotion": "happy",               // 8 类之一
  "ts_ms": 1706000100000,
  "trace_id": "tr-abc123def456"
}
```

### 2.2 结束标记

```json
{
  "type": "npc_say_stream_done",
  "npc_id": "npc_wang_boss_001",
  "session_id": "sess-abc123",
  "sentence_count": 3,
  "complete": true,
  "ts_ms": 1706000103000,
  "trace_id": "tr-abc123def456"
}
```

### 2.3 LLM 输出格式（prompt 端，XML tag 流式）

要求 LLM 输出 token 流，每句末尾插入 emotion tag：

```
<emotion=happy>来了您嘞！</emotion>
<emotion=neutral>几位？</emotion>
<emotion=happy>坐坐，马上给您沏茶。</emotion>
<end>
```

**为什么 XML tag 流式（不 JSON line）**：
- ✅ 所有 LLM 兼容（无 JSON mode 依赖）
- ✅ token-by-token 解析（流式友好）
- ✅ 调试友好（直接读 raw token 流）
- ⚠️ 字符串正则解析（复杂度可控）

### 2.4 sentence splitter 规则

agent-os 新组件 `SentenceSplitter`：

- 缓冲 LLM 流式 token 块（buffer size ≤ 200 char）
- 检测闭合 tag `<emotion=X>...</emotion>` + 句末标点（。！？~）→ 切出一句
- 输出：`(text, emotion)` 元组流
- EOF 或 `<end>` tag → 触发 `npc_say_stream_done`
- 单句生成 > 8s → 截断当前句子 + emotion=neutral（**降级 §3**）

### 2.5 session_id 来源

- api-gateway `/v1/npc/:id/talk` 入参 **可选** 携带 `session_id`
- agent-os 内部生成：`f"sess-{uuid4().hex[:12]}"`，60min TTL 内存 map
- session_id 用于 web 端排序 + 去重 + 重连补帧（轻量）

## §3 错误处理 + 降级

### 3.1 错误码（沿用 stage1 R_001~R_010，新增 R_011~R_015）

| 码 | HTTP | 含义 | 触发 |
|---|---|---|---|
| R_011 | 502 | LLM_STREAM_FAIL | stream() 中途报错 / 超时 |
| R_012 | 502 | LLM_STREAM_TIMEOUT | 单句生成 > 8s |
| R_013 | 400 | EMOTION_PARSE_FAIL | `<emotion=X>` X 不在 8 类内 |
| R_014 | 502 | REDIS_PUBLISH_FAIL | Redis pub 报错 |
| R_015 | 400 | SESSION_NOT_FOUND | session_id 过期 |

### 3.2 降级矩阵（按优先级）

1. **LLM 流式失败** → 降级到 stage1 `action_dispatcher.py` BT 固定台词 + 返回 R_011
2. **LLM 单句超时** → 截断当前句子 + emotion=neutral + 发包 + 后续句子继续
3. **emotion 解析失败** → emotion=neutral（不阻塞句子推送）+ 写 R_013 日志
4. **Redis pub 失败** → agent-os 内存 buffer 100 条 + 异步重试（1s/3s/10s 三次）
5. **ws-gateway 频道未订阅** → 静默丢包（运维告警靠 ws-gateway fanout 计数）
6. **web 端断连** → 重连时按 `session_id` + `last_sentence_idx` 拉取 buffer（agent-os 内存保留 5min）
7. **LLM JSON mode 不可用** → fallback 到 XML tag 流式（本 spec 默认 XML，不涉及）

### 3.3 流式结束语义

- LLM 输出 `<end>` tag → 发 `npc_say_stream_done`（`complete=true`）
- 流式中断（断网/超时） → 等待 3s 后发 `npc_say_stream_done`（`complete=false`）
- 心跳：agent-os 每 30s 发 `npc_say_stream_ping`（运维可观察）

## §6 风险 + 缓解

| 风险 | 缓解 |
|---|---|
| LLM 流式延迟 > 句子节拍推送目标（<1s） | 单句超时 8s + 截断降级；observability 监控 p95 |
| emotion 标签 LLM 不稳定（生成失败率高） | validator 降级 neutral + 离线评估集 200 条调优 |
| Redis pub/sub 消息丢失 | 短时（<100ms）丢失可接受；长时走 session buffer 重连补帧 |
| 5 NPC prompt 调优工程量大 | prompt 模板集中文件 + 离线评估集 + 单 NPC LLM 调优循环 |
| web 端 typewriter 体验差（句子突然出现） | NPCDialog CSS transition 200ms fade-in 减弱视觉冲击 |
| LLM 月成本超支 | CostTracker 已有（stage1），单回合多 30% token 计入预算 |
