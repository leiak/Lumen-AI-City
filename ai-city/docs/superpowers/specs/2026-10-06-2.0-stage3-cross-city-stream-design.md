# 2.0 阶段 3 B1 — 跨城 NPC 流式（Cross-City NPC Streaming）

> **Status:** Draft（待 user review）
> **Date:** 2026-10-06
> **Branch:** main（继承 2.0 阶段 1+2 GA）
> **Track:** 2.0 阶段 3 平行轨道 1（4 条轨道中的跨城流式转发）
> **Reference:** `docs/2.0-ROADMAP.md` §阶段 3 第一轨道 + ADR-0007 + Stage 2 Spec

## Summary

在 2.0 阶段 2「同城内 NPC 流式 + emotion」基础上，把流式对话延伸跨过联邦边界：当玩家在 A 城与 LLM 部署在 B 城的 NPC 对话时，每一句节拍包应在 B 城 agent-os 生成 → 经 B 城 a2a-gateway → A 城 a2a-gateway → A 城 Redis → A 城 ws-gateway → 玩家浏览器，端到端延迟体感接近同城。

**核心变更**：
- a2a-gateway 新增 **流式转发 RPC**（gRPC server streaming），把 B 城 `say_stream()` 节拍流过桥回 A 城
- A 城 a2a-gateway 收到节拍 → 转发到 A 城 Redis `aicity:npc:say_stream`（**复用 stage 2 频道**）
- 跨城 session 由 A 城 a2a-gateway 拥有 sid；B 城侧只作为 LLM worker，不持有 session 状态
- 重连补帧端点 `GET /v1/federation/sessions/{sid}/buffer`（**复用 SessionStore + 镜像 A2** 模式）
- 错误码 `R_016/R_017` 跨城流式专用

**不在范围**：3+ 城市的链式转发 / 跨城 session 持久化超过 60min / 跨城状态迁移 / 跨城 gamification。

## §1 背景

### 1.1 为什么需要跨城流式？

- **现状**：跨城 NPC 对话走 `POST /v1/cross_city/talk`，**只返回整段**（npc_b_* 命中路由表 → httpstat 探针 + 透传 body），玩家在 A 城看到 B 城 NPC 是"等 3-5 秒然后整段出现"
- **目标**：玩家在 A 城与 B 城 NPC 对话时，**句子级实时出现 + 句末 emotion 表情**，体感与同城内流式无差别
- **业务价值**：联邦协议的核心承诺 = "联邦后的 NPC 对玩家无感知"；流式是这条承诺的体验底线

### 1.2 Stage 2 已就绪的复用基座

| 模块 | 路径 | 跨城可复用点 |
|---|---|---|
| `Publisher` | `apps/agent-os/src/agent_os/stream/publisher.py` | B 城 agent-os 仍 publish 到 B 城 Redis `aicity:npc:say_stream` |
| `SessionStore` | `apps/agent-os/src/agent_os/stream/session_store.py` | A 城 a2a-gateway 持 sid，B 城 LLM worker 无状态 |
| `EmotionValidator` | `apps/agent-os/src/agent_os/stream/emotion_validator.py` | B 城 agent-os 仍做 emotion 验证 |
| `crosscity.Dial` | `apps/a2a-gateway/internal/crosscity/client.go` | A 城 a2a-gateway 拨 B 城时复用 mTLS gRPC（**但需扩展到 server streaming**） |
| `Router` + 路由表 | `apps/a2a-gateway/internal/router/table.go` | npc_id → 远端 gRPC endpoint 解析（已就绪） |
| `aicity:npc:say_stream` | ws-gateway 多频道订阅 | A 城 ws-gateway 不需改造，节拍包自然落 A 城 Redis |
| Stage 2 错误码 R_011~R_015 | `apps/agent-os/src/agent_os/errors.py` | agent-os 内部错误 |

### 1.3 跨城 vs 同城的微差异

| 维度 | 同城 | 跨城 |
|---|---|---|
| 节拍包来源 | agent-os → Redis → ws-gateway | agent-os (B) → Redis (B) → a2a-gateway (B) → **a2a-gateway (A)** → Redis (A) → ws-gateway (A) |
| session 所有权 | agent-os | a2a-gateway A 拥有 sid；B 城只接受 trace_id |
| 重连补帧 | `GET /v1/npc/sessions/{sid}/buffer` | `GET /v1/federation/sessions/{sid}/buffer`（镜像） |
| 错误码 | R_011 ~ R_015 | 上述 + R_016/R_017（跨城流式专用） |

## §2 Goals / Non-Goals

### 2.1 Goals

1. **跨城流式低延迟**：A 城玩家点 B 城 NPC → 节拍包端到端延迟 < 800ms（目标值，TBD smoke 跑后调整）
2. **节拍包语义一致**：每条 beat 仍含 `npc_id / session_id / sentence_idx / text / emotion / ts_ms / trace_id`，与 stage 2 一致
3. **错误码语义清晰**：跨城联邦错误独立于 agent-os 内部错误（避免 502/504 误用）
4. **session 60min TTL**：A 城 a2a-gateway 持 sid；过期行为与 stage 2 一致（返 R_015）
5. **mTLS 复用**：沿用 stage 1 已建立的 aicity-CA 联邦 PKI（`GRPC_TLS_CERT/KEY/CA` env）
6. **复用 Redis 频道**：A 城 a2a-gateway 转发节拍包到 `aicity:npc:say_stream`，ws-gateway 不感知跨城
7. **可重连补帧**：玩家重连后能从 `sentence_idx=N` 补帧

### 2.2 Non-goals（YAGNI）

1. **3+ 城市的链式转发**（A → B → C）：本 spec 仅 A↔B 单跳；链式需引入 ttl 循环检测
2. **跨城 session 持久化超过 60min**：本 spec 沿用 SessionStore 60min TTL；超过视为 stage 4+
3. **跨城 NPC 状态迁移**：NPC 状态 / 记忆 / emotion 历史均留在 NPC 所在城市；A 城不持有
4. **跨城 gamification**：跨城任务 / 跨城经济 / 跨城声望 → stage 4+
5. **跨城流式断线重试**：B 城 a2a-gateway → A 城连接断开时，节拍包丢失视为 done(complete=false)；不在 a2a-gateway 内做 buffer
6. **流式期间玩家打断**：与 stage 2 一致（不做 stream cancel）
7. **跨城 emotion 历史持久化**：与 stage 2 一致（emotion 仅 UI 临时态）

## §3 架构

### 3.1 拓扑（5 跳 + 1 桥接）

```
┌─────────────────────┐
│ 玩家（city A 浏览器） │
└──────────┬──────────┘
           │ 1. POST /v1/npc/:id/talk  (npc_id 含 _b_)
           ▼
┌─────────────────────┐
│  api-gateway (A)    │ ── 识别 npc_id 含 _b_ → forwardCrossCity
└──────────┬──────────┘
           │ 2. POST /v1/federation/say_stream (HTTP SSE, JSON)
           ▼
┌─────────────────────┐
│  a2a-gateway (A)    │ ── 路由表查 B 城 endpoint
│  拥有 session_id    │
└──────────┬──────────┘
           │ 3. mTLS gRPC server streaming
           │    rpc SayStreamForward(stream SayBeat) returns (stream SayBeat)
           ▼
┌─────────────────────┐
│  a2a-gateway (B)    │ ── 收到远端 dispatcher 调用
│  透传，无状态       │
└──────────┬──────────┘
           │ 4. HTTP POST /v1/npc/say_stream_internal (or in-process)
           ▼
┌─────────────────────┐
│  agent-os (B)       │ ── dispatcher.say_stream()
│  LLM 流式           │     SentenceSplitter + EmotionValidator
└──────────┬──────────┘
           │ 5. publish 到 B 城 Redis aicity:npc:say_stream
           ▼
┌─────────────────────┐
│  a2a-gateway (B)    │ ── 订阅 B 城 Redis，按 session_id 过滤
│  SayStreamForward   │     把节拍包 forward 回 A 城
└──────────┬──────────┘
           │ 3 反向流：流式回 A 城
           ▼
┌─────────────────────┐
│  a2a-gateway (A)    │ ── 收到节拍包 →
│  SayStreamForward   │   1. SessionStore.append(sid, ...)
│  client             │   2. publish 到 A 城 Redis aicity:npc:say_stream
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│  ws-gateway (A)     │ ── 多频道订阅（含 sentence_at + moved_at）→ 玩家 WS
└─────────────────────┘
```

### 3.2 协议选择：gRPC server streaming（推荐） vs HTTP SSE

| 维度 | gRPC server streaming | HTTP SSE |
|---|---|---|
| 复用现有 mTLS 栈 | ✅ `crosscity.Dial` 已就绪 | ⚠️ 需重新搭 mTLS + 双向 cert 校验 |
| 序列化类型安全 | ✅ protobuf / protojson | ⚠️ 纯 JSON，需手写 DTO |
| 流控 / 背压 | ✅ gRPC 内置 | ❌ SSE 无 |
| Debug 难度 | ⚠️ 需 grpcurl | ✅ curl + 浏览即可 |
| 与 stage 1 联邦 RPC 一致性 | ✅ 现有 5 RPC 均为 gRPC | ❌ 需新 wire |
| 首字节延迟 | ~5ms（HTTP/2） | ~30ms（HTTP/1.1 + chunked） |

**决策**：选 **gRPC server streaming**。理由：与 stage 1 联邦一致 + 复用 mTLS + 类型安全；HTTP SSE 留作后续 web RPC 调用式（web → a2a-gateway）。

### 3.3 Session 模型（**A 城 a2a-gateway 拥有 sid**）

| 字段 | 所在位置 |
|---|---|
| `session_id` | A 城 a2a-gateway 内存（SessionStore 镜像） |
| `npc_id` / `city_b` | A 城 a2a-gateway 内存 |
| `buffer` | A 城 a2a-gateway 内存（每个 beat 入 buffer） |
| `trace_id` | A 城 a2a-gateway 生成，下发各 B 城 |
| `LLM 上下文` | B 城 agent-os 内部（不在联邦可见） |

**关键不变式**：B 城是无状态的 LLM worker；不持有 session；所有 buffer / 重连补帧逻辑在 A 城。

### 3.4 认证与权限

- **mTLS**：A 城 a2a-gateway 拨号 B 城时使用 stage 1 已建立的 aicity-CA 联邦 PKI（`GRPC_TLS_CERT/KEY/CA` env 已配置）
- **Capability**：复用 stage 1 的 `card.Capabilities` 机制；新增 `stream_forward` capability（无 cap → F_017 同服务器拒掉）
- **API Key**：HTTP SSE 入口端 `POST /v1/federation/say_stream` 仍走现有 `A2A_HTTP_API_KEY` Bearer（与 `cross_city/talk` 同模式）

### 3.5 错误码（新增 R_016/R_017）

| Code | HTTP | gRPC | 触发场景 |
|---|---|---|---|
| `R_008 CrossCityRefused`（已存在） | 403 | PermissionDenied | 路由命中但 ACL 拒 / capability 缺失 |
| `R_016 CrossCityStreamFail`（新） | 502 | Unavailable | gRPC 流中途中断 / B 城 agent-os 报错 |
| `R_017 CrossCityStreamTimeout`（新） | 504 | DeadlineExceeded | 整段流 > 30s 无 done 包（与 stage 2 单句 8s 超时不同；此处为整段超时） |

R_016/R_017 由 **A 城 a2a-gateway 产出**（在 SayStreamForward client 端兜底），不传到 B 城；B 城自身错误仍走 R_011~R_015 透传。

## §4 Proto / API 表面

### 4.1 新 gRPC RPC（`a2a.proto` 扩展）

```protobuf
// 在现有 a2av1.A2AGatewayServer 上新增 SayStreamForward RPC
service A2AGateway {
  // ... 既有 5 个 RPC ...

  // B1: 跨城流式转发。client (A 城) → server (B 城)；
  // 双向流（client 发 SayRequestInit 一次 + server 流式返回 SayBeat）。
  rpc SayStreamForward(stream SayStreamMessage) returns (stream SayBeat);
}

message SayStreamMessage {
  oneof msg {
    SayRequestInit init = 1;          // 首帧必须 init
    SayHeartbeat   heartbeat = 2;      // A 城每 5s 发一次保活
  }
}

message SayRequestInit {
  string npc_id = 1;                  // npc_<city>_<slug>
  string player_input = 2;            // 玩家输入文本
  string session_id = 3;              // A 城生成的 sid
  string trace_id = 4;                 // A 城生成
  repeated ContextMessage context = 5; // 上文（仅本 session 内）
  string player_id = 6;
}

message SayHeartbeat {
  int64 ts_ms = 1;
}

message SayBeat {
  string type = 1;                     // "npc_say_stream" / "npc_say_stream_done"
  string npc_id = 2;
  string session_id = 3;
  // for type=npc_say_stream:
  optional int32  sentence_idx = 4;
  optional string text = 5;
  optional string emotion = 6;
  // for type=npc_say_stream_done:
  optional int32  sentence_count = 7;
  optional bool   complete = 8;
  // common:
  int64 ts_ms = 9;
  string trace_id = 10;
}

message ContextMessage {
  string role = 1;                     // "user" / "assistant"
  string content = 2;
}
```

### 4.2 新 HTTP SSE 入口（`api-gateway → a2a-gateway`）

```
POST /v1/federation/say_stream
Authorization: Bearer <api-key>   # 与 /v1/cross_city/talk 同模式
Content-Type: application/json

{
  "npc_id": "npc_b_grace_healer_001",
  "player_id": "uuid-...",
  "player_input": "你好",
  "context": [{"role": "user", "content": "..."}, ...],
  "session_id": "sess-...",        # 可选；缺省由 A 城 a2a-gateway 生成
  "trace_id": "tr-..."             # 可选
}

→ 200 OK
Content-Type: text/event-stream
Transfer-Encoding: chunked

data: {"type":"init", "session_id":"sess-...", "trace_id":"tr-...", "ts_ms":...}

data: {"type":"npc_say_stream", "sentence_idx":0, "text":"您好！", "emotion":"happy", ...}

data: {"type":"npc_say_stream", "sentence_idx":1, "text":"...", ...}

data: {"type":"npc_say_stream_done", "sentence_count":N, "complete":true, ...}

```

错误（非 200）：

| 错误码 | HTTP | 说明 |
|---|---|---|
| `R_009` | 400 | npc_id 缺失或格式错 |
| `R_011` | 502 | npc_id 路由表未命中（远端城市不可达） |
| `R_016` | 502 | 远端 gRPC 流失败 |
| `R_017` | 504 | 整段流超时 |
| `R_008` | 403 | ACL / capability 拒 |

### 4.3 跨城 session 重连补帧端点

```
GET /v1/federation/sessions/{sid}/buffer?from_idx=N
Authorization: Bearer <api-key>

→ 200 OK
{

```

## §5 数据流详解

### 5.1 A 城 api-gateway 入口

`POST /v1/npc/:id/talk` 当 `npc_id` 含 `_b_` 时：
- **当前**：forwardCrossCity → `POST /v1/cross_city/talk`（HTTP 整段）
- **新路径**（B1）：forwardCrossCityStream → `POST /v1/federation/say_stream`（HTTP SSE）
- 触发条件：当且仅当 session 内已有 buffer（即走 stage 2 流式入口失败而改走跨城？）。**初版简化——直接走流式，整段模式保留作为 fallback**

**简化决策**：B1 初版统一走流式入口（`POST /v1/federation/say_stream`）；`POST /v1/cross_city/talk` 保留为 fallback（玩家端在 SSE 失败时回退）。

### 5.2 A 城 a2a-gateway 流式入口

`POST /v1/federation/say_stream` handler：
1. 解析 body → 生成/继承 `session_id` + `trace_id`
2. SessionStore.create / get（60min TTL 镜像）
3. 路由表 Lookup(npc_id) → 远端 endpoint
4. 启动 goroutine：
   - mTLS gRPC dial 远端 a2a-gateway
   - 首帧发 `SayRequestInit`
   - 监听 `SayBeat` 流：
     - 写 SessionStore buffer
     - publish 到 A 城 Redis `aicity:npc:say_stream`
5. SSE 写入 chunked response（透传到 api-gateway）
6. 流结束 / 错误 → SSE 终止 + 关闭 gRPC

### 5.3 B 城 a2a-gateway 流式接收

`SayStreamForward` server handler：
1. 接首帧 `SayRequestInit` → 校验 npc_id 是本城的（cross-city 后路由表再查一次，命中本城 → 走 agent-os；未命中 → 透传到下一城，本 spec 不实现 → R_008 拒）
2. 启动 goroutine 调用 agent-os HTTP `POST /v1/npc/say_stream_internal`（与 stage 2 走 agent-os 单 Redis publish 类似，但**B 城 a2a-gateway 订阅 B 城 Redis `aicity:npc:say_stream`**，按 session_id 过滤）
3. 把收到的 SayBeat 写入 gRPC server stream 流式回 A 城
4. done / 错误 → 关闭流

### 5.4 B 城 agent-os

- **不变**：dispatcher.say_stream() + Publisher.publish_beat/publish_done（stage 2 已就绪）
- B 城 a2a-gateway 订阅 B 城 Redis `aicity:npc:say_stream` 后，按 session_id 过滤拿到本 session 的 beats

## §6 错误处理

| 错误码 | 触发场景 | HTTP | gRPC code | 处理策略 |
|---|---|---|---|---|
| `R_009` | npc_id 缺失 / 格式错 | 400 | InvalidArgument | 直接拒 |
| `R_011` | 路由表未命中（远端城市不可达） | 503 | FailedPrecondition | 返错给 api-gateway → 返 NPC_001 给玩家 |
| `R_008` | capability 缺失 / ACL 拒 | 403 | PermissionDenied | 拒 + 记日志 |
| `R_016` | gRPC 流中途中断 / B 城 agent-os 报错 | 502 | Unavailable | SSE 立即终止；前端改用整段模式回退 |
| `R_017` | 整段流 > 30s 无 done 包 | 504 | DeadlineExceeded | SSE 立即终止；前端降级到整段 |
| `R_015` | session 过期 / 不存在（重连补帧时） | 400 | NotFound | 返前端 404，提示"会话已过期" |

**降级矩阵**：

| 跨城流式失败 | 降级路径 |
|---|---|
| mTLS dial 失败（R_011） | 返 503 → 前端改走 `POST /v1/cross_city/talk` 整段 |
| SayStreamForward 启动失败 | 同上 |
| 流中途中断（R_016） | SSE 半截关闭；前端在 done timeout 后改走整段 |
| 流超时（R_017） | SSE 关闭；前端改走整段 |
| 远端 agent-os R_011 报错 | 透传 R_016 → SSE 关闭 |

**前端降级**：web client 在 SSE 入口 `onerror` 或 30s 超时后，回退调用 `POST /v1/npc/:id/talk`（整段模式）；整段模式走 stage 1 路径，与 stage 1 行为一致。

## §9 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| gRPC 流控在跨城延迟下背压 | A 城 buffer 满 → 丢包 | gRPC 内置背压；B 城 a2a-gateway 做 send queue 限速 |
| B 城 Redis 订阅延迟 | 节拍包到达 SSE 端延迟 +50~200ms | 接受；emotion 体感与同城内差别肉眼不可见 |
| 跨城 mTLS 证书轮换 | 双城需同步更新 | 沿用 stage 1 已建立的 cert 流程；新证书 TTL 30 天 |
| session 在 60min TTL 边界跨城断线 | 重连补帧时 R_015 | 文档化；session 在对话开始时创建；不延寿 |
| A 城 Redis 频道污染 | B 城 beats 混入 A 城频道 | 接受（同前缀 + 同字段；ws-gateway 已按 npc_id 过滤） |
| 流式 + 整段模式切换的玩家体验 | 切换时 SSE 半截 | web 端在 SSE 失败时透明降级到整段，不告诉玩家 |

## §10 显式不做（YAGNI）

- ❌ **3+ 城市链式转发**（A → B → C）— 留待 stage 4；本 spec 仅 A↔B 单跳
- ❌ **跨城 session 持久化超过 60min** — 沿用 SessionStore TTL；超过视为 stage 4+
- ❌ **跨城 NPC 状态 / 记忆 / emotion 历史迁移** — 状态留在 NPC 所在城
- ❌ **跨城任务 / 经济 / 声望** — stage 4+
- ❌ **流式期间玩家打断** — 与 stage 2 一致，不做 stream cancel
- ❌ **跨城 federation 双向流式（A 端 + B 端都说话）** — 本 spec 单向（玩家在 A；NPC 在 B）
- ❌ **OCEAN personality 派生 emotion 概率** — 独立轨道
- ❌ **BT 编辑器 v2 / Saga DSL 可视化** — 阶段 3 平行轨道
- ❌ **Push 通知 / 离线模式 / 客户端预测** — 阶段 4
