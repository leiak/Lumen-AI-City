## 目标

建立虚拟经济系统，驱动 NPC 商品交易、玩家间转账、动态通胀模型，让"AI 公民"形成真实消费闭环。

## 范围

### 在 v1 范围内
- 双货币：gold（玩家间 + NPC 售货）+ token（仅任务产出）
- 钱包 + 转账 + 玩家交易历史
- NPC 商品目录 + 玩家购买
- 中央银行发钞 + NPC sink（动态通胀）
- Kafka 3 topic 事件（observability 友好）
- Redis 余额缓存（read atomic）
- agent-os BT 加 1 action (`npc_sell_to_player`)

### 显式不做（v1 YAGNI）
- 创作者市场 / 分成（v2 接 3.0 子轨道 #2）
- PIPL/GDPR 合规（v1 不接数据导出，留接口）
- 移动端钱包 UI（仅 web）
- 多语言货币
- 跨城金币转账（仅同城，玩家跨城需 a2a-gateway 协议扩展，3.0 v2 推）
- 货币兑换（gold ↔ token 不可互换）
- 衍生品 / 拍卖 / 担保交易

### 服务组件

| 组件 | 端口 | 职责 |
|---|---|---|
| economy-service (FastAPI) | 8005 | 主服务，PG + Redis + Kafka producer |
| central-bank scheduler | embedded | 每 6h 跑 1 次发钞 |
| Redis | 6379 | `econ:{user_id}:gold` / `econ:{user_id}:token` |
| Kafka | 9092 | 3 topic emit |
| agent-os | 8006 (现有) | Phase C.1 + 新 action |

### 数据流

1. **玩家转账**：web POST → economy-service → PG 事务（双行 +/- 一对）→ Redis 更新 → Kafka emit `tx.completed`
2. **NPC 购买**：agent-os BT action / web POST → economy-service → PG 事务（gold 扣款 + product stock-1 + central_bank_sink 5%）→ Redis + Kafka
3. **中央银行发钞**：scheduler 6h → 算式 → 给所有活跃玩家 +N → Kafka `gold.emitted`
4. **Sink**：purchase 时自动 + admin 手动 → gold 销毁 → Kafka `gold.sunk`

## 数据模型（PG migration slot 07）

```sql
-- 双货币余额（int64 = 0.01 单位，足够 9×10¹⁵ 上限）
CREATE TABLE wallet (
    user_id      TEXT PRIMARY KEY REFERENCES player(id),
    gold_balance BIGINT NOT NULL DEFAULT 0 CHECK (gold_balance >= 0),
    token_balance BIGINT NOT NULL DEFAULT 0 CHECK (token_balance >= 0),
    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 不可变交易记录（append-only，审计 + 回溯）
CREATE TABLE transaction (
    id          BIGSERIAL PRIMARY KEY,
    tx_type     TEXT NOT NULL CHECK (tx_type IN
                   ('player_transfer','npc_purchase','central_bank_emit','npc_sink')),
    user_id     TEXT NOT NULL,
    counterparty_id TEXT,
    currency    TEXT NOT NULL CHECK (currency IN ('gold','token')),
    amount      BIGINT NOT NULL,
    balance_after BIGINT NOT NULL,
    product_id  BIGINT,
    trace_id    TEXT,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_tx_user_id_created ON transaction(user_id, created_at DESC);
CREATE INDEX idx_tx_type_created ON transaction(tx_type, created_at DESC);

-- NPC 商品目录（独立表，跨城共享）
CREATE TABLE product (
    id          BIGSERIAL PRIMARY KEY,
    npc_id      TEXT NOT NULL,
    name        TEXT NOT NULL,
    price_gold  BIGINT NOT NULL CHECK (price_gold >= 0),
    price_token BIGINT,
    stock       INTEGER,
    enabled     BOOLEAN NOT NULL DEFAULT true,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(npc_id, name)
);
CREATE INDEX idx_product_npc ON product(npc_id) WHERE enabled;

-- 中央银行账本
CREATE TABLE central_bank_ledger (
    id          BIGSERIAL PRIMARY KEY,
    event_type  TEXT NOT NULL CHECK (event_type IN ('emit','sink')),
    currency    TEXT NOT NULL CHECK (currency IN ('gold','token')),
    amount      BIGINT NOT NULL,
    reason      TEXT,
    trigger_user_id TEXT,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_cbl_created ON central_bank_ledger(created_at DESC);
```

**幂等性表：** （v1 不强制 — 用 Redis SET NX + first-response cache，TTL 24h）

```sql
-- v1.1 optional audit trail；v1 用 Redis `econ:idem:{key}` SET NX (TTL 24h)
CREATE TABLE IF NOT EXISTS idempotency_key (
    key         TEXT PRIMARY KEY,
    tx_id       BIGINT REFERENCES transaction(id),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 设计要点

- `amount` 正负号统一；emit=+，sink=-，transfer 写 2 行（out + in）
- `balance_after` 写时快照 → 不需要 rebalance 即可审计
- `stock` 可空 → null = 无限库存（NPC 杂货铺），非 null = 限量（武器/服饰）
- `currency` 枚举 2 类，未来扩 ('gem','premium') 改 enum
- `transaction` 是不可变 append-only；UPDATE/DELETE 不允许（PG trigger）
- `wallet.gold_balance >= 0` CHECK 约束防止超扣

## agent-os BT 集成（Phase C.1 扩 6 action）

`apps/agent-os/src/agent_os/bt/actions.py` 加 1 action：

```python
def npc_sell_to_player(product_id: int, currency: str, state: BTState) -> Status:
    """NPC 通过 product_id 售货给玩家。

    调 economy-service POST /v1/wallet/purchase（带 trace_id 关联 BT tick）；
    SUCCESS 写 state.last_purchase；FAILURE 写 state.last_purchase_error。
    网络异常 / 余额不足 → FAILURE（BT 短路，不会卡死 BT 循环）。
    """
```

**集成点：** `apps/agent-os/src/agent_os/dispatcher.py` `say_stream()` 后置 hook — BT 跑完触发 `npc_sell_to_player` action；不阻塞流式。

**Action 注册表：** 5 → 6 entries。Phase C.1 的 `TEST_ACTIONS` 测试豁免槽保留。

## 中央银行机制

### 发钞（emit）调度

- `central_bank_scheduler` 后台 task（asyncio），每 6h 跑 1 次（env `EMIT_INTERVAL_HOURS=6`，v1 默认 6h；可调）
- 公式：`emit_amount = base * active_player_count * (1 - gold_supply / sink_capacity)`
  - `base=100` 金币/玩家/周期（env `EMIT_BASE=100`）
  - `sink_capacity=10000` 金币软上限（env `SINK_CAPACITY=10000`）
  - 活跃玩家 = 24h 内有 wallet 写入的 user 数
  - 算式保证：金币存量高时少发，低时多发（反通胀）
- 写 `central_bank_ledger` 1 行 + 给所有活跃玩家钱包各 +N（N = emit_amount / active_count）
- Kafka emit `gold.emitted` 事件

### Sink 触发

- **自动 sink**：每次 NPC 售货自动从全系统金池扣 5% 沉淀 → 销毁（env `NPC_SINK_RATIO=0.05`）
- **手动 sink**：admin `POST /v1/admin/central-bank/sink`
- Sink 上限：`MAX_SINK_RATIO=0.05`（单次 sink 占该玩家余额上限）
- 写 `central_bank_ledger` 1 行 + Kafka emit `gold.sunk`

### 硬上限

`MAX_GOLD_PER_PLAYER=100000`（防 inflation bug 导致金币溢出）。

## Kafka 事件

| Topic | Payload | 谁订阅 |
|---|---|---|
| `econ.tx.completed` | `{tx_id, tx_type, user_id, currency, amount, balance_after, ts}` | observability / Saga |
| `econ.gold.emitted` | `{event_id, amount, active_player_count, reason, ts}` | observability / 报表 |
| `econ.gold.sunk` | `{event_id, amount, trigger_user_id, reason, ts}` | observability / 报表 |

- Producer: `aiokafka` 异步发（fire-and-forget，不阻塞事务）
- Consumer: v1 不强制订阅；observability hook 在 admin-portal / Grafana 后面再加

## 风险

| 风险 | 缓解 |
|---|---|
| 中央银行发钞 bug 导致金币无限膨胀 | MAX_GOLD_PER_PLAYER 上限 + 发钞公式有界（不可能溢出） |
| 并发双花（玩家同时 2 笔转账） | PG `SELECT FOR UPDATE` + transaction 表唯一约束 |
| Kafka producer 失败导致事件丢失 | fire-and-forget + observability 监控 lag；不阻塞事务 |
| Redis 缓存与 PG 不一致 | Redis 是 read-cache，PG 是 source of truth；写时双写（Redis set 后 PG commit） |
| NPC 商品价格被刷 | `MAX_GOLD_PER_PLAYER` 上限 + rate limit（每用户每分钟最多 10 笔 purchase） |
| 中央银行 scheduler 漏跑 | health check endpoint 暴露 last_emit_at；observability 告警 |
| agent-os BT action 阻塞 LLM 流式 | 不阻塞 — 异步 fire-and-forget；purchase 失败仅记日志 |
| 跨城金币转账（v1 不做） | a2a-gateway 协议扩展（v2）；v1 仅同城内转账 |
