# 1.0 版本边界与范围

> **定位**：1.0 = "MVP 公测切片"。原计划 §14 §Ⅰ.3 的 **M3 里程碑**：6 NPC + 1 玩家 + 1 剧本可跑。
>
> **不**等于"原计划 Sprint 3 全部完成"。是把当前进度对齐到原计划 MVP 公测的最小切片上，并把超出范围的所有工作显式切除。

---

## 〇、为什么需要这个 doc

到 Sprint 10 为止，项目完成了 16,000+ LOC 生产代码（Rust + Go），10 个微服务只有 stub，**核心愿景"玩家与 Agent 公民互动"还没有任何 demo 能跑通**。继续按原计划 24 周 12 Sprint 推进意味着：

- **叙事上没有 end**：BT 编辑器、Saga DSL、Push 引擎、联邦外部 Agent、经济系统、合规、创作者市场 —— 每条都是"再花 4 周"的独立大坑
- **关键缺口被掩盖**：NPC 行为引擎（agent-os）才是 MVP 的命门，但优先级排在 10 个 stub 服务后面
- **A2A 协议超建**：`a2a-gateway` 6,772 LOC + 11 PG 集成测，但 Sprint 10 仍无外部 Agent 接入；其完整度不匹配当前需求层级

**1.0 的目的不是"做完"，是"切开"**：定义一个能让 stakeholder 在 5 分钟内看完就能说出"我懂这是什么东西"的最小可演示闭环。

## 一、1.0 范围（必须包含）

### A. 已有能力（7 容器全部 healthy，验证不变）

| 能力 | 服务 | 验收 |
|---|---|---|
| 玩家登录 + JWT 鉴权 | api-gateway | `POST /v1/auth/login` 返 token，Bearer 鉴权通过 |
| 3×3 地图（9 tile） | world-engine | `GET /v1/tiles` 返 9 个 tile，5 NPC 种子可见 |
| 玩家移动 | world-engine + api-gateway | `POST /v1/world/move` 改坐标，Redis publish 实时事件 |

| WS 重连校准 | ws-gateway + web | Sprint 10 落地后，刷新或断网后 tile 数据自动校准 |

### B. 必须新做的（核心缺口）

| 缺口 | 为什么必须有 | 1.0 验收 |
|---|---|---|
| **NPC 行为引擎（agent-os 真的能跑）** | 没有它，玩家看不到任何"AI 公民"反馈 | 1 个 NPC 模板（王老板）在 3×3 地图上每 30s 走 1 步，玩家进 1 tile 范围内 NPC 主动 say 一句话 |
| **NPC 行为模板（npc-templates 真正填进数据）** | 现在 4 个文件 219 行只有 schema | `packages/npc-templates/wang_boss.yaml` 至少有：personality 字段、say 数组（5 句台词）、walk 模式（3 步走法） |
| **NPC ↔ 玩家互动入口** | 现在点 NPC 没反应 | WorldMap 点 NPC 圆点弹出小对话气泡（不接 LLM，纯脚本回复） |
| **1 条剧本"新玩家入场"** | 原计划 M3 DoD 之一 | 玩家首次登录 → 王老板主动打招呼 → 玩家回复（脚本化选择）→ 走完回 store |

## 二、1.0 范围（**显式不包含**）

> 每条都写"为什么不包含"——未来想加回来时知道当初为什么没做。

### 1.0 不做 LLM 集成
- **不做原因**：5 NPC × 每天大量决策 × Claude API 成本不可控；§10 规则的"chat_turns 6 回合强制收尾"是 2.0 才需要的设计
- **未来信号**：何时接 LLM？当 1.0 验证完"AI 公民能形成体验"后再加
- **依赖**：LiteLLM、多 Provider 抽象、Safe-LLM 全部延后

### 1.0 不做 a2a-gateway 联邦
- **当前状态**：`a2a-gateway` 6,772 LOC + 74 测试通过，但**无任何 producer/consumer**
- **不做原因**：联邦外部 Agent 接入需要先有"内部 AI 公民"才有意义（否则联邦进来只能跟玩家说话，跟"在线聊天室"无差别）
- **保留策略**：a2a-gateway **代码保留、协议稳定**（不再加新功能）；2.0 启动"1 个 openClaw Agent 接入并稳定运行 7 天"前不复活
- **依赖**：openClaw / workbuddy 适配器、mTLS、能力发现全部冻结

### 1.0 不做记忆 / Milvus / Neo4j
- **当前状态**：`memory-service` 83 LOC stub
- **不做原因**：1.0 NPC 行为脚本化，不需要"记住上次对话"；引入 Milvus + embedding 流水线是 2.0 的事
- **未来信号**：当 NPC 行为模板从"固定台词"变成"基于玩家历史的动态回复"时再启动

### 1.0 不做 Saga 剧本引擎
- **当前状态**：`saga-orchestrator` 85 LOC + `saga-worker` 57 LOC 都是 stub
- **不做原因**：1.0 唯一剧本"新玩家入场"是确定性脚本（NPC 移动 + 台词），不涉及多步补偿事务
- **未来信号**：当需要"3 NPC 各自行动 + 失败回滚"时再启动 saga-orchestrator

### 1.0 不做 BT 可视化编辑器
- **当前状态**：`bt-editor-api` 31 LOC + `apps/admin-portal` 68 LOC
- **不做原因**：1.0 行为树是手写 YAML，运营/策划通过编辑 `npc-templates/*.yaml` 配置 NPC；编辑器是创作者生态的入口，不是 MVP 入口
- **未来信号**：1.0 验证完"行为树能让 NPC 形成体验"后再做编辑器

### 1.0 不做 Saga DSL
- **不做原因**：同上，1.0 剧本是数据驱动（JSON / YAML）而非 DSL 文本
- **未来信号**：2.0+ 启动 saga-dsl 编译器

### 1.0 不做 Push / 通知引擎
- **当前状态**：`notification-engine` 62 LOC stub
- **不做原因**：1.0 玩家必须在线互动（WS 长连接），不需要 APNs/FCM
- **未来信号**：1.0 GA 后 1 个月启动"用户离线 30min 后推送"

### 1.0 不做离线同步
- **不做原因**：1.0 玩家必须连 WS，没有"离线写本地、连上同步"的需求
- **未来信号**：移动端 / PWA 启动时再做

### 1.0 不做客户端预测 / 协调
- **不做原因**：1.0 单城 9 tile，乐观更新 + 失败回滚已经够用
- **未来信号**：地图扩到 100+ tile、玩家移动延迟明显时再上 client-reconciler

### 1.0 不做经济系统
- **当前状态**：`economy-service` 23 LOC stub
- **不做原因**：1.0 NPC 互动是免费的；引入虚拟货币、信用、KYC 是商业模式的事

### 1.0 不做数据本地化 / 跨境
- **不做原因**：1.0 在 dev/staging 跑，不上 prod

### 1.0 不做监管合规（PIPL / GDPR / AI 内容标识）
- **不做原因**：1.0 不上 prod
- **未来信号**：GA 前 4 周启动

### 1.0 不做灾备 / RTO / Grafana 大盘 / 告警 SOP
- **不做原因**：1.0 是 dev demo，崩了就重启
- **未来信号**：1.0 GA 启动时同步做

### 1.0 不做压测 / 故障注入 / 24h 长期运行
- **不做原因**：1.0 是"能跑 5 分钟给 stakeholder 看"，不是"24h 不崩"
- **未来信号**：1.0 GA 前 2 周

## 附录 B：被"已完成"误导的 6,772 LOC a2a-gateway 怎么办

- **当前**：6,772 LOC + 74 测试 + 11 PG 集成测，**功能完整但无用户**
- **1.0 决策**：
  - 代码**完全保留**（这是有价值的协议实现）
  - 不再增加新功能（不接新 provider / 不加新 endpoint）
  - 不接入 compose（不进 1.0 的 8 容器）
  - CI 仍跑测（守住不退化）
- **2.0 启动条件**：
  - 1.0 GA + 至少 1 个 LLM-driven NPC
  - 出现具体"为什么需要联邦"的场景（不是"以防万一"）
  - Tech Lead 评审通过
- **风险**：a2a-gateway 1-2 年无用户，依赖升级、proto 演化可能让它与 2.0 需求脱节 —— 这是可接受的技术债
- **判断准则**：1.0 完成后每 6 个月评估一次 a2a-gateway 是否值得复活；若 2027 年还没场景，**正式标记 deprecated**
