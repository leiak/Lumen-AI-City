# Stakeholder FAQ

> **目的**：stakeholder 看完 demo 后最常问的 8 个问题 + 答案模板。
> **场景**：演示后 Q&A 10-30 分钟。

## Q1：这是不是写死的对话？不是 AI 吧？

**A**：对，1.0 是预设回复树（行为树驱动），证明 AI 公民这个体验形态能跑通。

2.0 接 LLM 后，同样的对话框架可以接真 AI 生成——体验形态不变，只是底层从"查表"变成"推理"。

**重点**：1.0 的"AI 公民"是**形态**而非"接 LLM"。形态成立 = NPC 主动 say + 多轮对话 + 持续运行。

## Q2：为什么只有 1 个 NPC？

**A**：1.0 切到最小闭环，先证明 1 个能跑。NPC 数量是数据问题，引擎已经能跑——加 1 个 NPC 加 1 个 yaml 而已。

2.0 会扩到 6 NPC + 多 NPC 互动 + NPC 寻路 + NPC 表情/头像。

**重点**：1.0 的"1 NPC"是**demo 简化**不是"技术上做不到"。

## Q3：那个 NPC 是不是会乱走？

**A**：对，NPC 会按 BT（行为树）自己走动——目前是按 schedule 走（10 点开门 / 22 点打烊 / 23 点听京剧）。

demo 看到的是"在 tile_0_0 站着"，因为 demo 时段是早上开门时段。

**重点**：NPC 行为是**确定性**的（schedule + BT），不是"乱走"——可预测可调试。

## Q4：多 tab 同步是什么原理？

**A**：WebSocket 推送。一个 tab 移动，所有 tab 都实时收到。

stakeholder 可以打开 2 个浏览器窗口试。

**重点**：同步是**实时**的（亚秒级），不是轮询。

## Q5：这个能商业化吗？什么时候上线？

**A**：1.0 是内部 demo 形态，**不能直接上线**。商业化要等 2.0——加 LLM + 创作者市场 + 合规。

1.0 跑通后我们内部可以拿 demo 给客户看"形态是什么样的"，但交付要 2.0 起。

**重点**：1.0 = **形态 demo**；2.0 = 商业化版本。

## Q6：对比其他游戏有什么差异？

**A**：**核心差异**：NPC 是 AI 公民，不是脚本。玩家走近会主动互动——这是传统 RPG 没有的。

形式上是 2.5D 俯视城邦，本质是 AI 公民持续运行的世界。

**重点**：1.0 的**最差异化**是"NPC 主动 say"——传统 RPG NPC 站桩不动，玩家走近不会主动打招呼。

## Q7：为什么不做 LLM？不是更智能吗？

**A**：LLM 成本高 + 不可控 + 需要合规。1.0 用 BT + 脚本化选择树证明体验形态成立。

2.0 接 LLM 时体验不变——只是 NPC 说的话从"预设"变成"生成"。

**重点**：1.0 的"无 LLM"是**成本/合规考虑**，不是"技术上做不到"。

## Q8：代码复杂度？团队规模？

**A**：1 个工程师 + 1 个产品 + 半个设计，4 周做完 1.0。当前代码 ~16K LOC，加 1.0 后预估 +3K。

团队规模不放大，工程效率主要靠 1.0 切得够小。

**重点**：1.0 是**MVP 闭环**而非"完整游戏"。团队规模和工期匹配 MVP 边界。

## 加分问题（stakeholder 可能问但没列在 §三）

### Q9：可以改 NPC 的对话内容吗？

**A**：可以。`packages/npc-templates/wang_boss.yaml` 是文本配置，改 yaml 即可。改完 `docker compose restart agent-os`。

### Q10：可以加更多 NPC 吗？

**A**：可以。加一个 `xxx.yaml` 文件到 `packages/npc-templates/`，把 `enabled: true`，重启 agent-os。1.0 demo 不演示多 NPC，但技术上已支持。

### Q11：演示需要联网吗？

**A**：不需要。所有 8 容器本地跑，断网可演示。

### Q12：可以同时多玩家吗？

**A**：技术上支持（多账号 demo / admin / 加新玩家），1.0 demo 单玩家演示是为了简化。多玩家演示需要切 2 浏览器登不同账号。

### Q13：商业化定价？

**A**：不在 1.0 范围。2.0 才讨论（创作者市场 + 订阅模式 + B2B API 等）。

### Q14：用户数据怎么存？

**A**：1.0 demo 玩家是种子数据（initdb 注入），无用户上传数据。2.0 才考虑数据本地化 / GDPR / 合规。

### Q15：什么时候能开 Beta？

**A**：1.0 GA 后立刻开内部 beta（公司内同事试用）。公开 beta 要等 2.0 GA。

## 不该答的问题

> 有些问题**不该答**——不是不能答，是答了反而误导 stakeholder

### ❓ "1.0 多久能上线？"

**为什么不该答**：1.0 是内部 demo 形态，"上线"需要商业版本（2.0+）。
**该怎么答**："1.0 不直接上线。1.0 GA 后 1-2 个月开 2.0，2.0 是商业化版本。"

### ❓ "能不能加这个 feature？"

**为什么不该答**：stakeholder 提的 feature 90% 在 1.0 范围外（plan §六 拒绝清单）。
**该怎么答**："我记下来，看 2.0 范围合不合适。1.0 范围是 [链接到 ROADMAP]。"

### ❓ "对比竞品 XX 怎么样？"

**为什么不该答**：1.0 演示中不引入竞品对比（避免技术讨论）。
**该怎么答**："1.0 的核心差异点是 NPC 主动 say，其他细节可以演示后单独聊。"

### ❓ "这个技术栈用什么？"

**为什么不该答**：技术栈对 stakeholder 不重要，且容易引出技术讨论。
**该怎么答**："技术细节在 1.0-ROADMAP.md 有。如果有具体技术问题，演示后单独约 Tech Lead。"
