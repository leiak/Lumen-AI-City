# 4.0 M3 Plan — Editor v2 + Production Hardening

> **Status:** Completed（2026-10-14）
> **Parent:** [4.0-ROADMAP.md](4.0-ROADMAP.md)
> **Goal:** 把 M2 的 Agent 模板闭环升级为可运营的编辑器链路，并启动生产基础设施硬化。

## Scope

### P0 — M2 productionization

| # | 任务 | 验收 |
|---|---|---|
| P0.1 | 重建并部署 a2a-gateway / web ✅ | 容器使用最新 M2 代码 |

### Track C — Creator editor chain

| # | 任务 | 验收 |
|---|---|---|
| C1 | Agent 草稿接入 BT Editor ✅ | Agent Console 可加载、编辑、校验、保存版本、沙箱试运行和回滚草稿 |
| C2 | BT 编辑前校验 ✅ | 深度、引用、节点数、环路在保存前拦截 |
| C3 | 编辑器试运行 ✅ | 使用草稿数据，不写运行时状态 |
| C4 | Saga DSL 可视化编辑 ✅ | 图谱可拖拽连线/删除/编辑属性，结构校验通过后才可导出 YAML |

### Track D — Production infrastructure

| # | 任务 | 验收 |
|---|---|---|
| D1 | Redis ACL / namespace 隔离 ✅ | 服务账号最小权限，Redis key/频道统一 `aicity:` 边界 |
| D2 | Redis 生产配置审查 ✅ | ACL 保持强制，RDB/AOF、maxmemory、slowlog、metrics 与告警就绪 |
| D3 | Kafka 主题与消费组巡检 ✅ | 关键经济事件不丢、可重放 |
| D4 | Milvus / etcd / MinIO 存储基线 ✅ | 健康门禁、生产凭证与内网隔离 |

### D2 Redis production configuration

- Configuration:
  - `maxmemory` 可通过 `REDIS_MAXMEMORY` 配置，默认 `512mb`。
  - 淘汰策略必须从 Redis 支持的 8 种策略中选择，默认 `allkeys-lru`。
  - RDB 保留三档快照；AOF 开启且 `appendfsync everysec`，rewrite 期间不阻塞 fsync。
  - slowlog 阈值 10ms，保留 256 条；latency monitor 阈值 100ms。
  - 关闭 debug 与 module 命令；数据目录挂载独立 named volume。
- Metrics:
  - 新增 `redis-exporter`，使用独立的 `metrics` ACL 账号，只允许 `PING` / `INFO`。
  - Prometheus 抓取 job：`aicity-redis`。
- Alerts:
  - `Redis_Down`（P0）
  - `Redis_Memory_Usage_High`（P1，90% 持续 10m）
  - `Redis_Evictions_Increasing`（P1）
  - `Redis_Rejected_Connections`（P1）
  - `Redis_Slowlog_Growing`（P2）
- Production override:
  - 移除旧 `requirepass` 单账号模式。
  - 生产 Compose 继续使用 ACL 启动脚本和服务专用 URL。
  - 生产环境必须显式提供全部 `REDIS_ACL_PASSWORD_*`；不再有 Redis 密码默认值。
- Validation:
  - `docker compose config`: **PASS**
  - production overlay `docker compose -f docker-compose.yml -f docker-compose.prod.yml config`: **PASS**
  - Prometheus YAML 解析: **PASS**

### D3 Kafka canonical topics + reliable consumers

- Topic contract:
  - Canonical manifest: `deploy/kafka/topics.env`。
  - Economy: `econ.tx.completed`、`econ.gold.emitted`、`econ.gold.sunk`、`econ.market.purchased`。
  - Cross-city: `econ.crosscity.gold.{reserved,refunded,credited,settled}`。
  - Saga: `saga.steps` 与 `saga.steps.dlq`；`saga.npc.action` 不再作为运行时 topic。
  - Init service 显式创建 partition/replication/retention/cleanup 配置；不再依赖 broker auto-create。
- Producer:
  - `acks=all`、`enable_idempotence=true`、5 次 broker retry。
  - Cross-city 使用 `global_id`，交易使用 `transaction_id`，金币事件使用 `player_id` 作 partition key。
  - 新增 `economy_kafka_send_total` / `economy_kafka_send_failures_total`。
- Saga consumer:
  - 所有 worker 使用共享 `saga-worker-group`，支持横向扩容。
  - 手动 commit；处理失败最多 3 次，最终写 `saga.steps.dlq`。
  - DLQ 消息包含 Base64 原始 payload 与错误信息；poison message 不再阻塞分区。
- Ops:
  - Kafka 关闭 auto-create，开启 healthcheck、持久化 `kafka_data` volume、7 天默认 retention。
  - `kafka-init` 在 `kafka` healthy 后创建/修改 canonical topics。
  - 新增 `kafka-exporter` 与 Prometheus job `aicity-kafka`。
  - 新增 broker down、consumer lag、producer send failure 告警。
