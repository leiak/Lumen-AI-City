## 三、Task 详情

### T01：dispatcher.say 改 Redis publish（0.5d）

**为什么必须**：Sprint 11 实现的 `dispatcher.say` 只打 log，玩家**听不到**王老板说什么。1.0 闭环需要王老板的台词通过 WS 推给浏览器。

**改动**：
- `apps/agent-os/src/agent_os/action_dispatcher.py::say()` 改实现
- 原：`logger.info("npc_wang_boss_001: would say: ...")`
- 新：`redis_client.publish("aicity:npc_dialogue", json.dumps(envelope))`
- envelope 格式（与 Sprint 10 ws-gateway 协议一致）：
  ```json
  {
    "type": "npc_dialogue",
    "trace_id": "<uuid>",
    "ts_ms": <int>,
    "payload": {
      "npc_id": "npc_wang_boss_001",
      "player_id": "<被 say 的玩家id>",
      "tile_id": "tile_0_0",
      "say": "<台词文本>",
      "options": [{"id": "ask_business", "text": "老板你这卖什么？"}, ...]  // 仅剧本触发时
    }
  }
  ```
- 5 个 NPC 字段从模板 `wang_boss.yaml` 读
- `trace_id` 用 google/uuid 生成

**验收**：
- 1 单测：mock redis，验证 publish 调用的 channel + payload
- 1 集成测：起假 ws subscriber，dispatcher.say 后收到 frame

**风险**：
- RedisPub 是 fire-and-forget（参 world-engine 模式）—— publish 失败仅 log warn；不阻塞 agent tick
- 不重试：丢了就丢了（1.0 接受；2.0 加 retry + dead letter）

### T05：POST /v1/npc/:id/talk endpoint（2d）

**新建 `apps/api-gateway/internal/handlers/npc.go`**：

```
POST /v1/npc/:npc_id/talk
Headers: Authorization: Bearer <jwt>
Body: {
  "choice": "ask_business",   // 用户选中的选项 id
  "player_id": "<uuid>"        // 玩家 id（JWT 解析后填）
}
Response 200: {
  "npc_id": "npc_wang_boss_001",
  "say": "我这有上好的女儿红...",  // NPC 下一句

Response 401: no token
```

- 返 reply

**注意**：
- 1.0 不持久化对话历史（每条对话独立）
- 1.0 不查 PG（npctemplates 走文件缓存）
- 1.0 不走 LLM（纯查表）
