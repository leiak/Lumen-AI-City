## 目标

在 1.0 闭环基础上，**桶 1 必做 4 项**（LLM-NPC + 记忆 + Saga + 跨城联邦）+ **桶 2 P1**（5 NPC 全开 + 表情），让 AI 公民从 BT 脚本升级为真正 LLM 驱动的 NPC。阶段 2 在阶段 1 基础上，引入 **LLM 真流式输出 + 8 类 emotion 标签**，让 NPC 对话从"等 30s 一句话"变成"句子级节拍推流 + 表情动画"。

| 内容 | 验收 |

| LLM 真流式（LiteLLM streaming） | agent-os `dispatcher.say_stream()` + 100 条 buffer 重试 |

| ws-gateway 多频道 | fanout 配置加 `aicity:npc:say_stream` |

## 错误码（阶段 2 新增 R_011~R_015）

| 码 | 含义 | 触发 |
|---|---|---|
| R_011 | LLM_STREAM_FAIL | LiteLLM 流式连接异常 |
| R_012 | LLM_STREAM_TIMEOUT | 单句 8s 超时 |
| R_013 | EMOTION_PARSE_FAIL | emotion 标签解析失败（降级 neutral） |
| R_014 | REDIS_PUB_FAIL | Redis pub 失败（buffer 重试） |
| R_015 | SESSION_NOT_FOUND | session_id 无效或已过期（60min TTL） |

## 风险（spec §6）

| 风险 | 缓解 |
|---|---|
| LLM 流式延迟 > 句子节拍推送目标（<1s） | 单句超时 8s + 截断降级；observability 监控 p95 |
| emotion 标签 LLM 不稳定（生成失败率高） | validator 降级 neutral + 离线评估集 200 条调优 |
| Redis pub/sub 消息丢失 | 短时（<100ms）丢失可接受；长时走 session buffer 重连补帧 |
| 5 NPC prompt 调优工程量大 | prompt 模板集中文件 + 离线评估集 + 单 NPC LLM 调优循环 |
| web 端 typewriter 体验差（句子突然出现） | NPCDialog CSS transition 200ms fade-in 减弱视觉冲击 |
| LLM 月成本超支 | CostTracker 已有（stage1），单回合多 30% token 计入预算 |
| Docker 镜像拉取受限（CN 网络） | 优先 daocloud 镜像；不阻塞代码提交 |
| Milvus 不可达 | PG fallback (recall_from_pg) |
| Saga 步骤超时 | R_007 错误码 + 重试 |
| 跨城 mTLS 证书过期 | renew-certs.sh（到期前 7 天） |

## 显式不做（spec §7 YAGNI — 阶段 2 推迟）

> 这些会反复被问，每次都用这一节回。

- ❌ **BT 编辑器 v2**（独立 sub-spec B，阶段 3 启动）— 当前 BT 是代码 + cpp.yaml，1.0/2.0 不需要给非工程师的可视化
- ❌ **Saga DSL 可视化**（独立 sub-spec C，阶段 3 启动）— 当前 Saga 是 YAML 数据 + saga-orchestrator 运行时，DSL 是创作者工具
- ❌ **跨城 NPC 流式转发**（阶段 3 延伸，a2a-gateway 已订阅 `aicity:npc:say_stream`）— 阶段 2 仅同城内可见，跨城留待阶段 3
- ❌ **emotion 历史持久化到 memory**（暂仅 UI 临时态）— 阶段 2 emotion 仅渲染一次，无长期存储
- ❌ **流式期间玩家中途打断**（"请等等" 类行为）— 当前阶段不做 stream cancel
- ❌ **NPC 表情 SVG 资源**（先用 emoji fallback，阶段 3 再做）— 阶段 2 只用 8 个 emoji，不做 SVG 动画
- ❌ **多语言 emotion 维度**（仅中文 8 类）— 英文/日文 emotion 留待全球化
- ❌ **emotion 标签的 OCEAN personality 派生**（阶段 3 探索）— 当前 prompt 不引用 OCEAN 5 维度

  - spec: `docs/superpowers/specs/2026-10-06-2.0-emotion-persistence-design.md`

NPC 对话现在携带对每位玩家的**情绪惯性**（快速衰减，τ=2h）和对**全玩家**的（慢速衰减，τ=24h）。当 LLM 流式输出 emotion 标签（阶段 2 的 8 类验证器）时，会持久化到 `memory_player_session.emotion`。下一回合：agent-os 拉近期 + 全局历史 → Python 端 `exp_decay_weight()` 衰减 → 注入 `【最近情绪氛围】` 到 system prompt（带加权百分比）。

##### What shipped

- **Migration** `db/migrations/pg-schema-2.0-emotion.sql` — 加 `emotion TEXT` 列 + 复合索引 `(npc_id, player_id, created_at DESC, emotion)`
- **Aggregation** `agent_os.emotion.aggregate` — 纯数学模块，`exp_decay_weight()` + `aggregate_distribution()`（12 单测）
- **Repository** `agent_os.emotion.repository` — asyncpg 包装 `fetch_player_distribution()` + `fetch_global_distribution()`（5 测试）
- **Settings** `agent_os.emotion.settings` — env 驱动 dataclass，含 `EMOTION_INJECT_ENABLED` kill switch（6 测试）
- **Writer** `agent_os.memory.writer.write_emotions` — best-effort 写入 `memory_player_session`（3 测试）
- **Prompt injection** `agent_os.llm.prompts.get_npc_stream_prompt` — 向后兼容 kwargs（recent + global distributions）；渲染 `【最近情绪氛围】` 段（5 测试）
- **App wiring** `agent_os.app` lifespan + `agent_os.dispatcher.say_stream` — 启动期实例化 `EmotionRepository`；当 injection 开启时在 prompt build 前拉分布；INFO 记 latency（9 wiring 测试 + 6 dispatcher-emotion-hook 测试）
- **Acceptance** `scripts/acceptance_emotion_v0.py` — 6 步 E2E binary（mocked unit tests，8 测试）

##### Env vars（默认值）

| Env var | Default | Purpose |
|---------|---------|---------|
| `EMOTION_TAU_PLAYER_SECONDS` | 7200 (2h) | Per-player 衰减 τ |
| `EMOTION_TAU_GLOBAL_SECONDS` | 86400 (24h) | Per-NPC-global 衰减 τ |
| `EMOTION_PLAYER_LIMIT` | 50 | Per-player 扫描行数上限 |
| `EMOTION_GLOBAL_LIMIT` | 100 | 全局扫描行数上限 |
