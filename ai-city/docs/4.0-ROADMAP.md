# 4.0 ROADMAP — 全功能生产愿景

> **Status:** Draft（2026-10-13）
> **前置状态:** 1.0 / 2.0 / 3.0 已 GA，Production Core GA 清单见 [17-Production-Core-GA.md](17-Production-Core-GA.md)
> **目标读者:** 产品 / 后端 / 前端 / 基建 / Agent 生态

## 1. 目标

从「能跑通的生产核心骨架」进入「可运营的全功能城市」。4.0 不再按单一版本追加功能，而是围绕四类角色补齐能力闭环：

| 角色 | 现状 | 4.0 目标 |
|---|---|---|
| 玩家 | 能移动、对话、购买、转账 | 有完整城市体验和清晰的成长路径 |
| 创作者 | 能上架 / 购买模板和分成 | 有完整的创作、调试、发布、经营工具链 |
| Agent | 能注册、发现、脚本对话 | 能稳定参与城市、创建内容、协作 |
| 运营 | 有 dashboard 和告警 | 有生产级安全、合规、扩缩容能力 |

## 2. 轨道划分

### Track A — 玩家体验 / 城市前端

**目标：** `/city` 从演示页升级为完整玩家界面。

范围：

1. 地图 / 相机 / 玩家移动体验统一（含触屏）
2. NPC 交互升级：流式对话、情绪、记忆提示、购买入口
3. 钱包 / 库存 / 交易记录玩家端可视化
4. 任务 / Saga 进度面板
5. Agent / 玩家身份区分展示

验收：

- 玩家可从进城 → 对话 → 购买 → 查看资产，全程无需开发者工具
- 移动端基础可用
- E2E 覆盖 20 条以上玩家路径

### Track B — Agent 能力与生态

**目标：** Agent 成为城市一等公民。

范围：

1. Agent 对话 UI（当前只有协议层）
2. Agent 创建 / 编辑 NPC 模板
3. Agent 行为权限边界：移动、交易、创建、协作分级授权
4. Agent ↔ Agent 会话协议落地 + 审计
5. Agent SDK / 示例仓库迭代

验收：

- Agent 可注册、对话、创建 NPC 模板并上架（灰度）
- 所有 Agent 高风险动作有审计和限流
- 至少 3 个不同实现的外部 Agent 可接入

### Track C — 创作者工具链

**目标：** 把 BT / Saga 从工程工具变成创作者工具。

范围：

1. BT 编辑器 v2（节点级编辑 + 校验 + 试运行）
2. Saga DSL 可视化编辑（从只读升级到可编辑）
3. 模板调试预览（沙箱城市 / 沙箱钱包）
4. 创作者经营报表（销量、收益、留存）
5. 模板版本管理 + 回滚

验收：

- 非工程师可完成一个 NPC 模板从创建到上架
- 模板发布前必须通过沙箱校验
- 创作者能看到核心经营数据

### Track D — 生产基础设施与合规

**目标：** 支撑真实用户规模。

范围：

1. Redis ACL / TLS / 命名空间隔离
2. Kafka / Milvus / etcd / Minio 生产集群化
3. 多副本部署 + 滚动升级 + 回滚演练
4. 数据导出 / 删除 / 同意管理（PIPL / GDPR）
5. 成本与配额体系（LLM、存储、带宽）

验收：

- 干净机器一键部署 + 全量验收
- Redis 数据面无裸奔访问
- 用户数据可导出、可删除
- 生产栈 7 天稳定性演练

## 3. 里程碑

| 里程碑 | 范围 | 估算 |
|---|---|---|
| M0 | 本路线图评审 + 轨道负责人确认 | 0.5 周 |
| M1 | Track A 玩家闭环 + Track B Agent 对话 UI | 3–4 周 |
| M2 | Track B Agent 创建 NPC + Track C 沙箱调试 | 4–5 周 |
| M3 | Track C 编辑器 v2 + Track D Redis/Kafka 硬化 | 5–6 周 |
| M4 | 合规 + 多副本 + 7 天稳定 | 4 周 |

M1 / M2 / M3 可并行推进，但每个轨道内部按顺序交付。

## 4. 依赖关系

| 依赖 | 影响轨道 | 说明 |
|---|---|---|
| Agent 权限模型 | B / C / D | Agent 创建 NPC、交易、上架都需要统一授权 |
| 沙箱钱包 / 沙箱城市 | C | 模板试运行不能污染生产经济 |
| Redis ACL | A / B / D | 前端与 Agent 的高频通道都依赖 Redis 稳定性 |
| Kafka 集群化 | C / D | Saga 与经济事件是创作者工具的基础 |
| 统一审计 | B / D | Agent 和创作者动作都要可追溯 |

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 范围再次膨胀 | 每个轨道先做 M1 最小闭环，再扩功能 |
| Agent 权限设计不足导致滥用 | 先灰度 + 全审计 + 限流，再放开创建能力 |
| 创作者工具复杂度过高 | 优先模板 + 表单化，编辑器 v2 放后 |
| 本机性能结论误用到生产 | 用干净机器 / 云环境重测 |
| 合规接口设计晚 | Track D 与 M1 并行启动数据模型 |

## 6. 显式不做（4.0 YAGNI）

- NFT / 玩家拥有权
- 多语言货币与海外本地化
- 衍生品 / 拍卖 / 担保交易
- 完整 3D / LOD 城市
- 大规模 Agent 联邦自治

## 7. 下一步

1. 确认 M1 优先级：建议先做 Track B 的 Agent 对话 UI，因为协议已就绪、用户可感知度最高。
2. 为 M1 拆任务清单和验收脚本。
3. Track D 的 Redis ACL 可以提前启动，不阻塞 M1。
