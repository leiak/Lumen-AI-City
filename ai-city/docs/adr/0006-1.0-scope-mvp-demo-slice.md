# ADR-0006: 1.0 版本范围切到 M3 MVP Demo 闭环

> **状态**：Accepted
>
> **日期**：2026-09-07
>
> **决策人**：@tech-lead @product-lead @ai-lead
>
> **影响范围**：`apps/*` 全部服务、`docs/1.0-*` 全部 1.0 文档、`README.md` 顶部 banner

## 背景（Context）

原 24 周 / 12 Sprint / $700K 计划（M1-M4 四阶段 + 7 个里程碑）按 §07-MVP 与 ADR 文档落地。
Sprint 9（ws-gateway 实装 + web 切轮询）结束后做复盘，发现项目**没有明确的终点**：

1. **范围漂移**：14 篇文档涉及 LLM / Milvus / Kafka / Saga / 联邦 / 创作者市场 / 经济 / 合规 / 灾备 / 压测 / K8s 至少 11 个**未实现**领域；stakeholder 5 分钟讲不清"1.0 是什么"
2. **超建反讽**：`a2a-gateway` 6772 LOC + 74 测试通过但**无 producer/consumer**；10 个 stub 服务合计 < 1K LOC（仅 Dockerfile + main.py）
3. **核心缺口未补**：1.0 必需的"agent-os 行为引擎真的能跑"还是 stub 状态
4. **进度无衡量**：M3 里程碑（原 MVP = 6 NPC + 1 player + 1 storyline）没有 Definition of Done

需要做出明确范围决策，给项目一个可交付的终点。

## 决策（Decision）

**1.0 = M3 MVP 最小切片** —— stakeholder 5 分钟看完能说"我懂"的可演示闭环。

具体范围（4 项 MUST + 8 容器保留 + a2a-gateway 冻结）：

### 1.0 范围（MUST）

| 项 | 内容 | 落地 |
|---|---|---|
| **8 容器** | postgres / redis / world-engine / api-gateway / ws-gateway / web / a2a-gateway / agent-os | docker-compose |
| **agent-os 行为引擎** | Python 3.12 + FastAPI + BT runtime（3 节点：Sequence/Selector/Action）| `apps/agent-os/` |
| **1 NPC 模板** | `wang_boss.yaml`（OCEAN + speech_style + backstory + schedule + bt + say.greeting + say.welcome + talk_tree）| `packages/npc-templates/` |
| **点 NPC 弹气泡** | NPCDialog.tsx（状态机：empty/showing/waiting-reply/showing-reply）| `web/src/components/` |
| **1 条剧本** | welcome storyline（玩家首次进 tile_0_0 触发；3 句随机 + 5 选项）| `packages/npc-templates/wang_boss_storylines/welcome.yaml` |
| **多 tab 实时同步** | ws-gateway 多频道（player_moved + npc_dialogue）| Sprint 10 已铺路 |
| **acceptance_1_0 binary** | 5 步端到端验收（login/walk/approach/NPC主动say/玩家回复）| `apps/a2a-gateway/cmd/acceptance_1_0/` |
| **2 个 1.0 必新 endpoint** | `POST /v1/npc/:id/position` + `POST /v1/npc/:id/talk` | api-gateway handlers |

### a2a-gateway 处置（意外发现的超建）

- **1.0 期间**：代码保留 / 不加新功能 / 不进 8 容器 demo 路径 / CI 仍跑测
- **2.0 启动条件**：1.0 GA + 1 个 LLM-NPC + 具体"为什么需要联邦"场景
- **2027 年仍无用户**：正式 deprecated

### 工期估算（基于 Sprint 11 + 12 拆解）

| Sprint | 范围 | 工时 |
|---|---|---|
| Sprint 11 | agent-os 骨架 + 1 NPC 模板 + world-engine MoveEntity | 14d |
| Sprint 12 | 玩家↔NPC 互动 + 1 条剧本 + acceptance_1_0 + 录屏 | 20d |
| Sprint 13 | 缓冲周（默认不触发） | 0-5d |
| **合计** | | **34d ≈ 6.8 周** |

原 1.0-ROADMAP 预算 4-6.5 周，超 0.3-2.8 周。**接受超期**（仍在 1.5 个月内可交付）。

## 备选方案（Considered Alternatives）

### 方案 A：按原 24-week 计划继续

- ✅ 范围完整，2.0+ 提前准备
- ❌ stakeholder 看不懂"我们在做什么"
- ❌ 工时 6 个月（24 周 × 0.5 人月）
- ❌ 1 个工程师 4 周完成的部分 = 项目总投入的 1/24，性价比极低

### 方案 B：纯 demo 版（无 BT、无 agent-os、纯脚本）

- ✅ 最快（2 周）
- ❌ 没有"AI 公民"实际形态
- ❌ stakeholder 演示完无法证明扩展性
- ❌ 2.0 必须重做 80%（BT/agent-os/loop）

### 方案 C：MVP + LLM（接 Claude API）

- ✅ NPC 对话更"AI"
- ❌ 成本高（每次 say 调 LLM，单 demo $5-10）
- ❌ 不可控（同样的输入不同输出）
- ❌ 合规风险（用户数据送第三方）
- ❌ 演示网速依赖

### 方案 D：MVP + 1 个完整 NPC（采纳）

- ✅ 4-6 周可演示闭环
- ✅ 演示稳定（预设对话，不依赖外部 API）
- ✅ 形态成立（NPC 主动 say + 多轮对话）
- ✅ 2.0 接 LLM 时形态不变
- ⚠️ 范围比 stakeholder 期望小（1 个 NPC vs 6 个）

## 影响（Consequences）

### 正面

1. **明确终点**：6.8 周后 1.0 GA；stakeholder 5 分钟能讲清
2. **工程聚焦**：8 容器 + 4 个 MUST 项 vs 原 15 容器 + 24 周计划
3. **演示稳定**：BT + 预设对话，无外部依赖；stakeholder 任何时候都能看
4. **2.0 路径清晰**：BT 节点扩 Inverter + Condition；NPC 数量加 5；接 LLM 替换 dispatcher.say
5. **a2a-gateway 不浪费**：代码保留但不强制上线；2.0 启动条件明确

### 负面 / 风险

1. **范围比 stakeholder 期望小**：1 NPC + 9 tile vs 原 6 NPC + 30 tile
2. **6.8 周 vs 原 4-6.5 周**：超 0.3-2.8 周，需 stakeholder 接受
3. **降级矩阵触发条件模糊**：D17 还没 5/5 → 启动降级；判定时机需 Tech Lead 把握
4. **a2a-gateway 2027 deprecated 风险**：若 2.0 启动条件未满足，代码腐化

### 中和（trade-offs）

- **1 NPC vs 6 NPC**：选择 1 NPC + 王老板"完整 demo"（OCEAN + backstory + schedule + say + talk_tree）vs 6 NPC 各 3 行 stub；演示质量 >> NPC 数量
- **6.8 周 vs 4 周**：选择 6.8 周 + DoD 完整（acceptance_1_0 5/5 + 录屏 + CHANGELOG）vs 4 周 + 简化版（仅手动验证）；工程质量 >> 速度
- **不接 LLM vs 接 LLM**：选择 BT + 预设对话 vs LLM 生成；可控性 >> 智能度

### 成功判据（stakeholder 视角）

stakeholder 走出演示时能向同事复述 3 件事：

1. **"玩家走进城邦，NPC 会主动打招呼。"**（NPC 主动 say，1.0 核心）
2. **"玩家可以选话题，NPC 接着聊。"**（多轮对话，行为树）
3. **"5 步自动化验收都过了。"**（工程可信度）

如果只能记 1 件 → **NPC 主动 say**（1.0 最差异化）。
